# v2.4 Proposal — Stage-0 Feasibility Checkpoint

**Status: RATIFIED UNDER OWNER DELEGATION 2026-10-09; consumed the same day.**
This is the version `/gsd-new-milestone` consumed, at the milestone start
`5be02066`, the requirements `56741dc5` and the roadmap `6ce484c8`.

## In one paragraph

After v2.0–v2.3 nobody can yet say whether this project can work, because no
run has ever trained the specified recipe and no test has measured the
network's accuracy in physical terms. v2.4 answers the question with a
ladder of experiments. Each rung is cheaper than the next and adds one
difficulty. The network fits one system while seeing the true answer. Then
it learns the same system from the physics. Then it learns a small family
of systems. Last comes the full Stage-0 control run that the `trainex-r4`
ruling designed. Each rung's pass marks are written down before it runs. A
failure at any rung shows which part is the bottleneck. The milestone always
ends with a verdict: **go**, **change the training method**, or **rethink
the representation**. The owner then decides whether the project continues.

## The question, and why it is still open

| Question | What the record shows |
|---|---|
| Does the data pipeline and training machinery work? | Yes. v2.0 shipped the verify ladder, the real-data smoke test and interrupt/resume (`milestones/v2.0-ROADMAP.md`). |
| Can the network learn one trajectory? | Only a wiring check exists. On one trajectory, with the 13 starting-condition inputs set to zero, the data-matching loss fell at least 1,000-fold (Phase 38 NET-05, `pinn/verification/overfit_probe.py:1-9`, `:55`). It measured a loss ratio, not accuracy in physical terms. |
| Can the physics term alone, without data, learn even one system? | Never tested. |
| Has any training run executed the specified recipe? | No. The v2.0 pilot diverged from the specs in five verified ways (v2.1 audit). Generation 7 evaluated the physics on one trajectory per step (`milestones/v2.3-GAPS.md`, "Post-close finding"). |
| How far is the best trained network from the success bar? | Generation 7 is the latest and non-conformant. Its worst-case validation energy error over 227 validation systems was 15.65 at step 100 and 50.63 at step 900 (`runs/stage0-v23g7-seed42/validation.jsonl`). The bar is 1 × 10⁻⁵. Over the same steps the validation loss fell from 16,499 to 5,278. The network moved toward the data while its trajectories became less physical. |
| How hard is the target? | Never measured. Stage 0 is stable hierarchical triples over the full window `T = 10` (`ctl_instruction.md:138-153`, `:998`). Nobody has counted how many inner-binary orbits such a window contains, and that count is what decides how oscillatory the function to be learned is. |

**The success bar.** The held-out gate requires every held-out system to
reach `ε_H = max_t |(H(t) − H(0)) / H(0)| ≤ 10⁻⁵` (`ctl_instruction.md:567`,
`pinn_architecture.md:1087`). That is the tolerance used to admit the Brutus
integrator's own output into the dataset. Whether any neural network can meet
it has never been examined. v2.4 does not move the bar. It measures how far
each experiment lands from it.

## The design: a learnability ladder in front of the corrected control

An analogy: before entering a student for a final exam on every topic, check
whether they can work one problem with the answer key open. Then check one
problem from first principles, then a short problem set. Only then sit the
whole exam.

| Rung | What runs | Question it answers | Needs the conformance fix? |
|---|---|---|---|
| 0 | No training: a census of the Stage-0 data, plus the ruling's read-only checks on generation 7's checkpoints | How hard is the target, and does anything in generation 7 contradict the plan? | no |
| 1 | One system, data loss only, on 3 systems | Can the network represent a Stage-0 trajectory at all, when shown the answer? (the ceiling) | no |
| 2 | One system: (a) physics + IC loss only; (b) the full ratified loss, on the same 3 systems | Can the physics find the trajectory, alone and with data? | no: with one system every slot is the same trajectory, so the single-anchor defect cannot arise |
| 3 | 16 systems, the corrected trainer in diagnostic mode | Does the recipe still learn when the network must tell systems apart? | yes |
| 4 | The full Stage-0 control: 1,812 systems, 1,000 Adam steps, seeds 42, 41 and 43 | Does the causal front advance at full scale? (the ruling's readout) | yes |

Each rung is cheaper than the one after it, and each answers a question the
next depends on. Rungs 1 and 2 give the first real answer, before any of the
conformance engineering is done.

## The feasibility scorecard (draft; FEAS-01 freezes it before any rung runs)

**Metrics.** Each scored system is measured over the whole window, at the
reference trajectory's output times, against its Brutus reference:

- **Position error** of the network's trajectory, in two forms:
  - the three bodies' positions, normalized by the system's size;
  - the inner pair's separation vector, normalized by the inner separation,
    so that a good outer orbit cannot hide a wrong inner binary.

  FEAS-01 fixes the exact normalization.
- **Valid-horizon fraction** `h_δ`: the share of the window before the
  position error first exceeds `δ`, for `δ` = 1% and 10%.
- **`ε_H`**: the gate's own energy error, from the network's positions and
  autograd velocities.
- **The physics residual**, normalized by `R_ref`, reported for context.

Physical measures are scored; loss values are not.

**Tiers, per system:**

| Tier | Name | Condition |
|---|---|---|
| 3 | Integrator-grade | position error ≤ 1% over the whole window **and** `ε_H ≤ 10⁻⁵` (the locked held-out bar) |
| 2 | Accurate | position error ≤ 1% over the whole window **and** `ε_H ≤ 10⁻³` |
| 1 | Qualitatively right | position error ≤ 10% over the whole window |
| 0 | Not learned | below Tier 1; `h_δ` still shows where along the window it breaks |

**Budget rule.**

- Each arm's step budget is set from a short timing run before launch, and
  capped:
  - about 3 hours of machine time for a single-system arm;
  - about 8 hours for Rung 3;
  - the control keeps the ruling's 1,000 steps.
- An arm still improving at its cap is **budget-limited**, not failed. It
  gets one extension that doubles its budget. If it is still improving after
  that, it is reported as inconclusive, with its measured rate of
  improvement. FEAS-01 defines "still improving".

**Decision rule (the milestone verdict, FEAS-06):**

- **RETHINK-REPRESENTATION.** Rung 1 reaches Tier 1 on fewer than 2 of the
  3 panel systems.
  - Meaning: the network cannot represent a single Stage-0 trajectory over
    the window even when shown the answer, so no change to the training
    recipe can fix it.
  - Rungs 2–4 are skipped and the milestone goes straight to the verdict
    (gate G2).
- **PIVOT-TRAINING.** Rung 1 reaches Tier ≥ 1 on at least 2 of 3, but the
  ratified recipe does not. Any of these triggers it:
  - Rung 2b is below Tier 1 on 2 or more of the 3 systems;
  - Rung 3 is below Tier 1 on more than 4 of its 16 systems;
  - the control's readout is not branch (a).

  The bottleneck is then the training method. The verdict names which part,
  from the ladder's pattern and the readout branch.
- **GO.** All three hold:
  - Rung 2b reaches Tier ≥ 1 on at least 2 of 3;
  - Rung 3 reaches Tier ≥ 1 on at least 12 of 16;
  - the control's readout is branch (a).

  Next comes a Stage-0 production-training milestone: training to
  convergence, graded seeds, and the preserved held-out evaluation under its
  preconditions. Stage 1 is planned from there.
- **Reported, not gating: Rung 2a** (physics + IC only). If 2a fails where
  2b succeeds, the method works as a data-trained surrogate that physics
  regularizes, not as a solver that learns from the equations alone. That
  changes how the project describes its result, not whether it continues.
- **Distance to the bar.** The verdict reports the best `ε_H` any rung
  reached, by tier. If no rung reaches Tier 3, not even Rung 1 with the
  answer in view, then the locked 10⁻⁵ bar is out of reach for this
  architecture as configured. The owner decides at the verdict whether it
  stays the project's success criterion.

**Honest limit.** A 16-system run and a 1,000-step control cannot show how
well the network generalizes to unseen systems after full training. v2.4
reports the validation-panel scores as an early signal and leaves
generalization to the next milestone.

## The phases

Phases continue from 58. Every phase ends at a gate. A gate may skip,
re-order or insert later phases when its pre-registered condition fires.
**The milestone always ends with the verdict**: an early exit goes straight
to Phase 64 with the evidence in hand.

### Phase 61 — Conformance & Instrumentation

- **Question.** Does the trainer do what the ratified recipe says, for every
  slot in the batch?
- **Work** (the ruling's step 2):
  - **CONF-10** (`JD-0`). Physics rows, the monitor and validation use each
    slot's own IC13 and masses. An identity-dependent assertion checks it:
    perturbing a non-anchor slot's IC13 must change both the physics loss
    and the IC loss.
  - **CONF-11** (`JD-1`). The IC term is the mean over the selected slots.
  - **INST-06** (`JD-10`). The telemetry union.
  - **INST-07.** The diagnostic modes; graded runs refuse all three:
    - an observe-only guard that logs the step at which it would halt;
    - an explicit Adam-only switch;
    - an observe-only plateau detector.
  - **SPEC-07..10.** The clarifying amendments:
    - `JD-1`'s batch rule;
    - `OQ-2`, epoch = one optimizer step;
    - `OQ-3`, the invariant-B monitor contract transcribed into the spec;
    - the inherited GAP-56-02.
- **Gate.** Two checks must pass:
  - the identity-dependent assertion;
  - a mechanical code-versus-spec check of every changed contract. A passing
    plan verification is not evidence; v2.0 and generation 7 both passed
    their verifications while diverging.

### Phase 62 — Gates & the Small-Family Rung

- **Question.** With conformant code, do the causal weights respond on real
  training systems, and can the recipe learn a small family?
- **Work:**
  - **GATE-05** (the ruling's step 3):
    - `R_ref` re-measured by the ratified six-case procedure;
    - GATE-04 re-run;
    - the `OQ-1` check: at initialization, the frozen monitor's 256 training

    - `JX-1`'s conformant half at initialization.

  - A gate failure stops the line. The code is fixed, or the probe amended

  - If a gate cannot be fixed within the milestone, the verdict follows on
    the ladder's evidence.
  - Rung 3's result goes to the verdict. The control still runs: it tests
    the front at full scale, and its readout branch names the next arm.

## Risks and how the design handles them

| Risk | Handling |
|---|---|
| A budget too short makes "not learned" look like "can't learn" | The budget-limited rule and its one extension; inconclusive results are reported as such. |
| One system is an anecdote | Three systems spanning the census, and the 16-system rung. |
| The harness drifts from the trainer | It calls the trainer's own functions; tests prove it. |
| Machine time | Rungs 1–2 take hours. Rung 3 is capped at about 8 hours. The control is 3 × about 3.4 hours at about 12.3 s per step (`runs/stage0-v23g7-seed42/status.json`). Runs go one at a time, detached. |
| Memory (24 GB) | The harness has bounded memory, and the generation-2 monitor-memory lesson applies. |
| The scorecard thresholds are judgment calls | They are stated here and frozen by FEAS-01 before any rung runs. The owner can veto them until then. |
