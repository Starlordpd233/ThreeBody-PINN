# v2.3 Proposal — Causal-Weight/SIREN-Scale Recipe Adjudication

**Status: DRAFT, not yet owner-ratified.** Unlike the v2.2 proposal (which
recorded an already-ratified decision before drafting), this document proposes
structure for the owner to react to and adjust before `/gsd-new-milestone` is
run. Nothing here is binding until ratified.

## Why this milestone exists

v2.2 closed incomplete on 2026-08-17. It repaired all nine verified Stage-0
conformance divergences and re-ran Stage-0 under the corrected recipe — the
first run that was actually the specified experiment. That run HALTed at the
invariant-B causal-front gate, step 501, `front_idx=0` for the entire `N=500`
window. A bounded residual-frame conformance audit the same day established
this is **not** a further conformance defect: it is a design-calibration gap
between two independently-locked framework-spec sections. The locked SIREN
initialization (`pinn_architecture.md` §2.2, `ω₀=30`) produces a second
derivative of `O(10⁵)` at initialization; the locked causal-weighting formula
(§3.2, `w_n = exp(−η_c·Σ R̄_m)`, `η_c=1` on unnormalized `R̄`) was calibrated
for a converged network's residual of `O(1)`. Neither choice is wrong in
isolation — they were simply never checked against each other — but stacked,
the causal gate is saturated shut from step 0 and stays saturated: 15 of 16
collocation-point weights sit at the numerical floor for the entire run.

This was exactly the contingency v2.2's own goal statement named in advance:
*"If the conformant run still fails, that failure is the first real evidence
about the design, and recipe adjudication... is v2.3."* v2.3 is that
milestone.

**Full record:** `.planning/milestones/v2.2-GAPS.md` "Milestone close";

## Milestone goal

Get a properly grounded, externally researched recalibration decision for the
causal-weight/SIREN-scale mismatch — via the ERW build-design channel, not by
the agent inventing a number — implement it as a framework-spec edit (finally
legal here; SCOPE-30 does not carry forward), re-run Stage-0 under the
corrected recipe, and spend the single preserved held-out evaluation on a run
that actually trains.

**What this milestone does NOT do:** re-litigate the nine v2.2 conformance
repairs (settled, not reopened), re-run DIAG-05 (superseded, not
re-litigated — see the re-derivation), or open Stage-1+/PLAT-01..07 (still
blocked by the v2.0 `adjust` verdict until a `go` verdict is rendered here).

## ERW approach (needs owner decision)

Two live options, not mutually exclusive:

**Option A — decision-sheet-only.** Trainex-r2's Q3 already frames the
options (recalibrate `η_c`, normalize `R̄` against a reference scale, retune
SIREN `ω₀`, or redesign the curriculum mechanism) and explicitly defers to
the owner. Skip a new research round; the owner fills trainex-r2's decision
sheet directly, informed by the now-confirmed (not merely hypothesized)
mechanism. Fastest path.

**Option B — narrow `trainex-r3` supplement.** Commission a focused Route-B
(open-book) ERW round asking specifically: *"given confirmed init-time
R̄≈10¹⁰ from an ω₀=30 SIREN's second derivative against η_c=1 unnormalized
causal weighting, what's the corrected calibration, and by what evidence?"*
This sharpens trainex-r2's open hypothesis into a confirmed premise, which
may change what the research agent recommends versus reasoning about a
recipe that (per trainex-r2's own framing at the time) hadn't run. Costs one
ERW round-trip.

**This document does not choose.** Per the ERW runbook, an agent suggests
defaults and never decides — see the decision sheet in "How to land this."

## Risks

- **The recalibration might not be a single clean parameter change.** Trainex-r2's Q3 already flags that `R̄` normalization interacts with the causal front's *within-trajectory* curriculum semantics — fixing the saturation without breaking the intended pacing needs care, likely more than one iteration inside the ERW round.
- **A second causal-front failure under the new recipe is possible.** SCOPE-37's conformance-only-after-the-edit discipline exists precisely so a second failure is informative (a real recipe-adjudication miss) rather than another conformance leak.
- **Trainex-r2 is 2026-07-25-vintage** — pinned to a commit baseline before the v2.2 conformance repairs landed. Option B exists partly to re-ground the research against the now-repaired, now-conformant codebase state.
