# v2.2 Proposal — Stage-0 Conformance Repair and Valid Re-Run

**Why this is a proposal and not `.planning/` edits.** The v2.1 close is in flight
in another session: v2.1 is not yet archived, `.planning/ROADMAP.md` and
`REQUIREMENTS.md` are still the active v2.1 files, and `STATE.md` is held by that
session. This document is the collision-free form. Once the close lands, it feeds
`/gsd-new-milestone` directly — see "How to land this" at the end.

## Owner ratification recorded

**The evaluation policy is owner-ratified 2026-07-25** (ratified by "proceed" in
response to the recommendation and its proposed wording). Verbatim as ratified:

> One additional held-out evaluation is authorized for the corrected Stage-0
> implementation, conditional on (i) preflight conformance passing with zero
> unwaived divergences, (ii) RG-02 resolved, and (iii) validation-side gate metrics
> recorded for the run being submitted. Any evaluation beyond this one requires a
> new owner decision. No evaluation may be spent on a run that has not passed
> (i)–(iii).

This becomes requirement **EVAL-01** and scope boundary **SCOPE-28**. *If a
narrower ratification was intended, correct this before the milestone is created —
everything downstream depends on it.*

**Related clarification, also load-bearing.** The standing "do NOT re-run"
(v2.0 audit warning W-1; the exhausted-budget note) governs re-evaluating **the
v2.0 seed-42 checkpoint**, protecting the integrity of the v2.0 record and its
receipt-based refusal path. It is *not* a prohibition on evaluating a future model.
A corrected implementation is a new question, not a re-run. Without this
distinction stated in the requirements, v2.2 is impossible by construction.

## Milestone goal

Establish, for the first time, a **valid** test of the Stage-0 design: repair the
verified conformance divergences, prove the repair with gate-aligned instrumentation
and a preflight gate, re-run Stage-0 under the corrected recipe, and spend the one
authorized held-out evaluation on a run that is actually the specified experiment.
The milestone ends with a verdict on the *design* — which the v2.0 pilot never
produced, because what it graded was not the design.

**What this milestone deliberately does not do:** tune the recipe. If the
conformant run still fails, that failure is the first real evidence about the
design, and recipe adjudication (with the trainex-r2 resolution doc as a candidate
verdict source) is v2.3.

## Phases (46–52, continuing from 45)

**Phase 46 — Frame Resolution & Gate-Aligned Validation** (CONF-01, INST-01)
Ungated, first phase. Two cheap unblockers. Settles the last remaining way the next
run could be invalid, and gives a conservation signal where none exists.
**Branch point:** if CONF-01 shows the target frame *is* wrong, that is a sixth
divergence and a data-path defect rather than a loss-math one. Phases 47–48 grow.
Surface as an owner scope decision, never absorbed silently.

**Phase 47 — S_H Pipeline** (CONF-02, CONF-03)
Depends on 46 — `K0`/`Uabs0` are frame-dependent (`H' = D·H`), so the frame must be
settled before the median is computed. **The largest single work item in the
milestone**: a real preprocessing stage computing a dataset-wide statistic and
persisting it, not a config change. This is why the original implementation
substituted a per-anchor stand-in.

**Phase 48 — Loss-Math Conformance** (CONF-04..07, INST-02, TEST-01, TEST-02)
Depends on 47. Carries a **blocking owner checkpoint**: the GAP-45-01 `L_data`
reduction, surfaced with computed term magnitudes from the retained runs so the
choice is made against numbers. Ordering constraint inside the phase: CONF-04
before CONF-05, since the clip must be chosen against the corrected `R̄`.

**Phase 49 — Conformance Gate** (GATE-01..03, INST-03)
Depends on 48. **Owner checkpoint:** N for invariant B. Coordinate with the charter
workstream per SCOPE-32 — consume its deliverables if they land, implement the
minimum subset otherwise. The gate must exist before Phase 51 spends the look.

**Phase 50 — Valid Stage-0 Re-Run** (RUN-01, RUN-02)
Depends on 49. Training authorized. Exit criteria: preflight clean with zero
unwaived divergences; invariants hold for a full run; validation `ε_H` recorded and
characterized across three seeds. Iteration here is conformance-only.

**Phase 51 — The Authorized Evaluation** (RUN-03, EVAL-01)
Depends on 50. Verify the three preconditions, record the verification, invoke the
evaluator **once**. Produces the verdict on the design: go / adjust / rethink, the
v2.0 ACC-06 pattern. This is the first valid grade the design has ever received.

**Phase 52 — Diagnosis Re-Derivation & Handoff** (DIAG-05, VER-19, VER-20)
Depends on 51. Re-derives the Phase 44 diagnosis against the conformant run with its
acceptance check, closes traceability, and hands off the spec-amendment routing list.
If Phase 51 passed, the re-derivation records that the v2.0 failure is explained by
conformance divergence; if it failed, it produces the first evidence-grounded
diagnosis of the *design*.

## Owner checkpoints

1. **GAP-45-01 `L_data` reduction** (Phase 48) — blocking, presented with computed
   term magnitudes. Must not be auto-decided.
2. **N for invariant B** (Phase 49) — the front-advance window.
3. **Scope decision if CONF-01 reveals a frame defect** (Phase 46) — the branch point.
4. **The verdict** (Phase 51) — go / adjust / rethink.

## Risks

- **The single look is still spendable on an invalid run.** EVAL-01's preconditions
  reduce this but cannot eliminate it: preflight can only check what it knows to
  check. GATE-02's placeholder census is the broadest net available.
- **SCOPE-29 is the hardest boundary to hold.** Once a conformant run produces a
  number, the pull toward "just try a different λ" will be strong. That is v2.3.
- **The S_H pipeline may surface dataset facts** that interact with v1.5-locked
  contracts. Route as gaps, do not adjudicate inline.
- **Concurrent-workstream collision** on preflight/invariants. SCOPE-32 is the
  boundary; if the charter session moves fast, Phase 49 shrinks to integration.
