  🟠 High (P1) — should fix before executing

  H1 · The verification gate proves git metadata parity, not working-tree
  content parity — yet prints "exact state reproduced."
  Both gates (A7, B6) only diff a manifest of HEAD / counts / stash list /
  status --short. The manifest hashes nothing. git status --short reports that
  a file is modified, never its bytes. git fsck verifies committed objects —
  but the migration's whole point is the uncommitted dirty deltas (8 M files)
  and untracked bytes (6 files + requirements.txt), and those are exactly what
  neither gate checks. tar is byte-faithful so the happy path holds, but the
  success string overclaims. (Symlinks CLAUDE.md/GEMINI.md→AGENTS.md and
  untracked-file contents are the same blind spot.)
  Proposed fix: append a content digest to the manifest (e.g. hash of git diff
  HEAD + a sorted hash of untracked files), so the B6 diff actually catches
  content drift — or soften "exact state reproduced" to "git metadata parity
  confirmed." (adversarial, 75, verified)

  H2 · No "quiesce" step — and that's the one realistic way H1 bites you.
  Nothing tells you to stop editors/agents/Spotlight/Time-Machine before
  A4→A7. This repo is under active multi-agent work (there's a live locked
  worktree-agent). A content-only write between A4 (manifest) and A6 (archive)
  silently desyncs them, and because it's content-only it sails past the
  metadata gate (H1).
  Proposed fix: add an A0/A4 quiesce step (close editors, stop
  agents/background jobs, mdutil -i off "$REPO", pause Time Machine;
  optionally re-capture the manifest immediately before A6 and abort on
  drift). (adversarial, 75)

  H3 · The "no secret files were found" claim is unverified for the files that
  actually ride in the archive.
  Line 446 calls encryption "precautionary," but Scope (line 18) deliberately
  includes gitignored local config — .claude/settings.local.json (11.5 KB),
  .claude/scheduled_tasks.json, .context/ — the exact files that hold
  MCP/agent auth state. Nothing scans them before upload.
  Proposed fix: add a mandatory secret-scan of those included paths between A5
  and A6, gating the archive build on a clean result. (security-lens, 75)

  H4 · MANIFEST.txt is uploaded to the GitHub release unencrypted.
  A8 uploads MANIFEST.txt alongside the .age file. It contains your branch
  names, stash descriptions ("pre-delete-v13-closure-audit",
  "scs-gate-correction"), and the full dirty/untracked file-path list —
  readable in plaintext by anyone with repo read access (collaborators,
  repo-scoped tokens), no passphrase needed.
  Proposed fix: encrypt the manifest too (age -p -o MANIFEST.txt.age …,
  decrypt before the B6 diff), or add an explicit "this metadata is exposed"
  accept-decision. (security-lens, 100)
