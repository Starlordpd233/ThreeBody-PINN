## 1. Problem

`pinn_instruction/markdown_conversion/framework-specs/sampling_method.md` double-books the
4th Sobol coordinate `u_4`:

- **§1.1 "Low-Discrepancy Engine"** (line 90): "A Sobol engine with base 6 dimensions
  (3 for position + 3 for velocity) is used, plus optional extras (e.g., 1 for global
  scaling if enabled via `scale_range`)."
- **"Global Scaling (Optional)"** (line 109): maps `u_4` to the scale factor
  `s = s_min + (s_max - s_min) u_4`.
- **"Velocity Sampling"** (lines 115–117): assigns `(u_4, u_5, u_6)` to the velocity vector,
  with `v_i = Φ⁻¹(u_{3+i})`.

When scaling is enabled — which is the active standard quasi-random configuration
(`scale_range=(0.8, 1.2)`) — `u_4` is described as **both** the scale factor and the first
velocity component. The spec is internally contradictory. A reader (or a FUT-01 implementer)
cannot determine the intended allocation from the spec alone.

This was raised in the finding doc `docs/findings/addressing_sobol_sequence_suggestion.md`.
The finding's structural diagnosis is correct; its recommended fix ("Option A") turned out
to match reality (see §3).

## 3. The locked convention (Option A)

### 3.1 What the data-generation code actually does

`simulation_data/Scripts/ic_generation/ic_generation_utils.py`, class `EnhancedThreeBodySampler`:

- **Dimension** (lines 89–99): conditional.
  ```python
  self.use_scaling  = (scale_range[0] != scale_range[1])
  self.use_velocity = (velocity_scale > 0)
  self.sobol_dim = 3                          # base: position
  if self.use_scaling:  self.sobol_dim += 1   # +1 scale
  if self.use_velocity: self.sobol_dim += 3   # +3 velocity
  if self.rotate:       self.sobol_dim += 3   # +3 rotation (non-functional stub; rotate=False default)
  ```
- **Allocation** (`_process_sobol_batch`, lines 120–164): insertion order — position, then
  scale, then velocity. `idx` advances `0 → 3` (position), `3 → 4` (scale, if `use_scaling`),
  then `idx:idx+3` (velocity, if `use_velocity`).

For the standard config (`scale_range=(0.8, 1.2)`, `velocity_scale=0.1`), both flags are
True, `sobol_dim = 7`, and the allocation is:

| Sobol column (0-based) | Math index (1-based) | Physical role |
|---|---|---|
| 0, 1, 2 | `u_1, u_2, u_3` | Position (θ, φ, r) |
| 3 | `u_4` | Scale factor `s` |
| 4, 5, 6 | `u_5, u_6, u_7` | Velocity components |

This is **Option A** (the finding's recommendation): when scaling is enabled, the velocity
coordinates shift to `u_5, u_6, u_7`. The general dimension formula is
`d = 3 + δ_s + 3·δ_v`, with `δ_s = 1` if scaling is enabled and `δ_v = 1` if velocity
sampling is enabled. This formula is scoped to `rotate=False` (the standard configuration):
the constructor also has `if self.rotate: self.sobol_dim += 3`, but `rotate` defaults to
False, `_process_sobol_batch` consumes no rotation coordinates, and the code marks it a
future feature — so `rotate` is a non-functional, disabled-by-default stub, excluded from
the locked formula.

### 3.2 Why this matches the existing dataset

The existing standard quasi-random dataset
(`simulation_data/Data/ic_final/ic_standard_quasi_random/`) was generated by this code.
Locking Option A means the v1.4 spec **describes the data that already exists**. FUT-01,
implementing from this spec, will produce statistically equivalent data — no
framework-data mismatch.

Locking Option B (the alternative initially considered) would have specified a different
allocation from what generated the data, creating exactly the mismatch the user flagged.

### 3.3 Hierarchical ICs are unaffected

`generate_stable_hierarchical_systems` (lines 290–443) uses `np.random.uniform` only — no
Sobol sequence. The Sobol-allocation convention applies solely to standard quasi-random ICs.

**INSERT:**
> #### Sobol Coordinate Allocation Convention
>
> The Sobol coordinates $u_i$ use 1-based mathematical indexing throughout this document.
> Array indexing in implementation should be shifted accordingly.
>

>
> | Coordinate | Physical role | Drawn when |
> |---|---|---|
> | $u_1, u_2, u_3$ | Position of the free particle ($\theta, \phi, r$) | Always |
> | $u_4$ | Sampling-time size scale factor $s$ | $\delta_s = 1$ only |

> the preprocessing-time global scaling (by constants $D$, $V$, $T$) currently described in

> locked in v1.4 by Phase 18 (FRAME-04, scaling order) and Phase 19 (PHYS-01, the

> pipeline stages: this sampling-time $s$ is applied at IC generation; preprocessing scaling
> is applied after canonical rotation.

### Edit 4 — Rename "Global Scaling (Optional)" → "Sampling-Time Size Variability" (lines 108–111)

**FROM:**
> #### Global Scaling (Optional)
> An optional global scaling factor $s$ can be applied to all positions and velocities for
> added variety in system size. It uses an additional Sobol dimension, mapping $u_4$ to a
> user-defined range $[s_{\min}, s_{\max}]$ (default: $[1.0, 1.0]$, disabling it) via
> $s = s_{\min} + (s_{\max} - s_{\min})u_4$. For example, the script's main block enables it
> with $[0.8, 1.2]$ for quasi-random generation.
>
> When enabled, positions scale by $s$ and velocities by $s$. **Impact on Virial Ratio:**
> This changes $Q = 2T / |U|$ by a factor of $s^3$ (kinetic energy scales as $s^2$,
> potential as $s^{-1}$). Disable if preserving virial equilibrium is required.

**TO:**
> #### Sampling-Time Size Variability
> An optional sampling-time size scale factor $s$ can be applied to all positions and
> velocities for added variety in system size. The scale factor is sourced from the 4th
> Sobol coordinate (per the Sobol Coordinate Allocation Convention above) and maps to a
> user-defined range $[s_{\mathrm{lo}}, s_{\mathrm{hi}}]$ (default: $[1.0, 1.0]$, which
> disables it: $\delta_s = 0$) via
>
> $$s = s_{\mathrm{lo}} + (s_{\mathrm{hi}} - s_{\mathrm{lo}})\,u_4.$$
>
> For example, the script's main block enables it with
> $[s_{\mathrm{lo}}, s_{\mathrm{hi}}] = [0.8, 1.2]$ for quasi-random generation.
>
> When enabled, positions and velocities both scale by $s$. **Impact on virial ratio:**
> this changes $Q = 2T / |U|$ by a factor of $s^3$ (kinetic energy scales as $s^2$,
> potential as $s^{-1}$). Disable if preserving virial equilibrium is required. When
> $\delta_s = 0$, no Sobol coordinate is consumed for scaling and velocity coordinates take
> indices $u_4$–$u_6$ instead of $u_5$–$u_7$.
>
> **Distinct from preprocessing-time scaling.** This sampling-time $s$ is applied at IC
> generation, **before** the preprocessing pipeline. The preprocessing pipeline subsequently
> nondimensionalizes the state by constants $D, V, T$ (see the Disambiguation note above).
> Because the characteristic time $T = t_{\max}$ is a global constant, the sampled $s$
> survives preprocessing as variety in the dimensionless IC, manifesting through the
> virial-ratio distortion that propagates into $E$ and other invariants.
>
> **Symbol note.** The bounds are $s_{\mathrm{lo}}$ (low) and $s_{\mathrm{hi}}$ (high). They
> are deliberately written `s_lo`/`s_hi` rather than `s_min`/`s_max` to avoid collision with
> the minimum pairwise separation invariant (denoted `s_min` in the resolution doc's
> invariant set).

### Edit 5 — §1.2 "Velocity Sampling" (lines 113–119)

**FROM:**
> #### Velocity Sampling
>
> The next three Sobol coordinates $(u_4, u_5, u_6)$ are mapped to a 3D velocity vector
> $\mathbf{v}$ using inverse transform sampling from a normal distribution with mean 0 and
> standard deviation $\sigma = \text{velocity\_scale}$ (default 0.1):
>
> $$v_i = \Phi^{-1}(u_{3+i};\,\mu=0,\,\sigma=\text{velocity\_scale}),\quad i=1,2,3.$$
>
> The sampler then enforces total momentum conservation by adjusting the velocity of the
> fixed particle so that $\sum_i m_i \mathbf{v}_i = 0$.

**TO:**
> #### Velocity Sampling
>
> Per the Sobol Coordinate Allocation Convention, the velocity coordinates
> $(u_{4+\delta_s}, u_{5+\delta_s}, u_{6+\delta_s})$ are mapped to a 3D velocity vector
> $\mathbf{v}$ for the free particle using inverse transform sampling from a normal
> distribution with mean 0 and standard deviation $\sigma = \text{velocity\_scale}$
> (default 0.1):
>
> $$v_i = \Phi^{-1}(u_{3+\delta_s+i};\,\mu=0,\,\sigma=\text{velocity\_scale}),\quad i=1,2,3.$$
>
> For the standard configuration with $\delta_s = 1$, the velocity coordinates are
> $(u_5, u_6, u_7)$; when $\delta_s = 0$, they are $(u_4, u_5, u_6)$.
>
> The sampler then enforces total momentum conservation by adjusting the velocity of the
> fixed particle so that $\sum_i m_i \mathbf{v}_i = 0$.
>
> **Particle indexing note.** "Free particle" here refers to the sampled particle
> (particle 2 in the pre-canonical-ordering scheme of §1). Phase 18 (FRAME-02) applies
> canonical ordering that may permute particle indices in downstream artifacts; the velocity
> vector defined here still describes the same physical particle through the permutation.

  alternative; C — decoupled scale stream.
- **Confidence of impact:** HIGH — the wrong choice creates a framework-data mismatch
  between the v1.4 spec and the existing standard quasi-random dataset.
- **Status:** `RESOLVED-WITH-INSTRUCTION`.
- **Resolution note:** User instruction 2026-05-19 — lock Option A, matching

## 8. Flagged out-of-scope items

**Sub-conflict #1 — Velocity-momentum reconciliation (contradictory outcome distribution).**
`sampling_method.md` line 119 says momentum conservation is enforced "by adjusting the
velocity of the fixed particle." `ic_generation_utils.py` lines 170–171 perform a symmetric
split `v1 = v3 = -v2/2` (with the code comment "For equal masses, maintain zero total
momentum"). For equal masses both yield total momentum zero — they agree on momentum
conservation — but they are **contradictory in outcome distribution**: the `v1`/`v3`
