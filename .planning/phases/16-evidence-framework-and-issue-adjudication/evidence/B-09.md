Role of this check: supporting evidence (verifying a negative claim), NOT grounding for new

Distinct from Phase 18 D-10 where simulation_data IS grounding for sampling_method.md /
FRAME-03 (the spec describes data generated by the code; code wins on conflict).

Plummer softening
`r_safe = sqrt(||r||² + ε²)` preserves the force/potential matched pair cleanly
from one denominator: `F = -∇V` where `V ∝ 1/r_safe` and
`F ∝ r/r_safe³`. The additive potential `V_add ∝ -1/(||r||+ε)` has its own
valid gradient, `F_add ∝ r/(||r||·(||r||+ε)²)`, so additive softening is not
intrinsically invalid. The pre-Phase-19 spec paired additive potential prose
with a different residual-force denominator in active contracts, breaking the
matched-pair identity. Plummer is preferred because the matched pair is
algebraically inspectable from a single `r_safe` definition.

PINN framework, but incorrectly framed them as a "mismatch" when they serve
different purposes: training versus static invariants. The resolution doc
correctly separates them by purpose.
