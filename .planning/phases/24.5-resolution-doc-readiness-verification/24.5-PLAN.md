# Plan 24.5-01: Resolution Doc Readiness Verification

## Goal

Verify the consolidated resolution doc is ready for use as the candidate verdict source in Phases 25–29. Produce a readiness report (pass/fail per check, fix instructions for any failures) and a resolution-doc quick-reference map for downstream phases.

## Pre-execution gate

Before any task runs, confirm:

1. The consolidated resolution doc exists at the expected path under `pinn_instruction/markdown_conversion/framework-revisions/research_reports/02-data-pipeline-and-validation/`.
2. Phase 24 is marked COMPLETE in STATE.md.

If either gate fails, STOP and surface to the user. Do not proceed with partial artifacts.

## Tasks

### Task 1: Presence and structural check

**What:** Verify the consolidated resolution doc exists and has citable structure.

**Checks:**
- File exists, is non-empty, and is a single coherent document (not a raw concatenation of the 8 individual research outputs).
- Has numbered or clearly labeled sections that can be cited by line range (Phase 25 evidence packets require line-range citations per EVID-06).
- Has identifiable sections for each major topic area: data pipeline issues, validation metrics, sampling/precision, global-scale, and training-data format.

**Output:** PASS/FAIL with reason.

### Task 2: Finding-coverage crosswalk

**What:** Map every issue-02 finding to the resolution doc section that addresses it.

**Input:** `24-ISSUE-LEDGER.md` — 19 findings (B-06, B-11, M11, M12, M13, D7, G1–G5, SCS, SASD, IPR, PSC, D-03, D=6.694, footer, mass-drift).

**Process:**
- For each finding ID in the ledger, locate the resolution doc section that provides a verdict or recommendation.
- G1–G5 are synthesis views over their constituent findings (B-06, B-11, M11, M13, M12 respectively) — they share the same resolution doc section as their parent finding.
- Record the mapping as a table: `Finding ID | Ledger Title | Resolution Doc Section | Coverage Status`.

**Coverage status values:**
- `covered` — the resolution doc addresses this finding with a clear position.
- `partial` — the resolution doc mentions the topic but does not provide a definitive position.
- `silent` — the resolution doc does not address this finding at all.

**Output:** Crosswalk table. Flag any `partial` or `silent` entries as gaps.

### Task 3: DATA-xx consistency check

**What:** Check that the resolution doc's dataset-related claims are consistent with the Phase 24 verified facts.

**Input:** `24-VERIFIED-FACTS.md` — 13 CLM rows (CLM-01 through CLM-12, plus DATA-05 verdict row, plus CLM-13 pending row).

**Process:**
- For each CLM row with a `confirmed` or `corrected` verdict, check whether the resolution doc states or implies a different value.
- CLM-13 (D=6.694) is PENDING and routed to Phase 25 EVID-10 — the resolution doc's position on this is expected and should be recorded but not flagged as a contradiction (it is a contested convention, not a dataset fact).
- The DATA-05 row has a specific resolution (70 stale artifacts, rerun executed) — check the resolution doc is consistent with this outcome.

**Output:** Consistency table: `CLM ID | Verified Value | Resolution Doc Position | Consistent?`. Flag contradictions.

### Task 4: v1.4-locked convention compliance

**What:** Check the resolution doc respects the hard constraints that were listed in the Phase 23 framed research questions.

**Locked conventions to check:**

| Convention | Source |
|-----------|--------|
| 14D input contract `[τ, IC₁₃]` | v1.4 Phase 17 D-03 |
| Jacobi IC₁₃ vector (13 components) | v1.4 Phase 17 D-01 |
| Mass-weighted COM projection head | v1.4 Phase 17 D-02 |
| PHYS-03 softening outcome | v1.4 Phase 20 |
| Post-v1.3 SCS gate `ε_H > 10⁻⁵` / `SCS > −5` | v1.3 locked |
| PHYS-01 D convention | v1.4 Phase 20 |

**Process:**
- Scan the resolution doc for any recommendation that would violate these locked conventions.
- A recommendation to change a locked convention is not a violation — it is a scope observation. Record it but flag it as "scope: would require user decision."

**Output:** Compliance table: `Convention | Resolution Doc Position | Compliant?`. Flag violations.

### Task 5: Produce resolution-doc quick-reference map

**What:** Create a navigation aid for Phases 25–29.

**Contents:**
1. **Section index** — table of the resolution doc's sections with a one-line summary of what each covers.
2. **Finding-to-section mapping** — derived from Task 2's crosswalk, showing which resolution doc section to consult for each finding.
3. **Citation guide** — how Phase 25 should reference the resolution doc in evidence packets (file path, section format, line-range convention).
4. **Verdict-direction preview** — for each finding, a one-word indicator of the resolution doc's direction (e.g., "accept-as-stated", "recommends-change", "defers", "silent").

**Output:** `24.5-RESOLUTION-MAP.md` — standalone document that Phases 25–29 can consult without reading the full resolution doc first.

### Task 6: Produce readiness report

**What:** Compile all check results into the final readiness report.

**Contents:**
1. **Executive summary** — one-line verdict: READY, READY-WITH-CAVEATS, or NOT-READY.
2. **Check results** — consolidated PASS/FAIL from Tasks 1–4.
3. **Gap list** — any `silent`, `partial`, inconsistent, or non-compliant items with specific descriptions.
4. **Fix instructions** — for each gap, actionable instructions for the external consolidation agent. Format: what is missing, which finding it affects, what the fix should produce.
5. **Re-check protocol** — how to verify the fix when the consolidation agent delivers it (re-run the affected tasks only).

**Output:** `24.5-READINESS-REPORT.md`.

### Task 7: Gate decision

**What:** Based on the readiness report, determine whether Phase 25 can proceed.

**Decision rules:**
- **READY** (all checks pass, no gaps) → update STATE.md, Phase 25 is unblocked.
- **READY-WITH-CAVEATS** (minor gaps that do not block adjudication, e.g., a `partial` coverage on a finding that Phase 25 can independently resolve via EVID-10) → update STATE.md with caveats noted, Phase 25 proceeds with awareness.
- **NOT-READY** (silent findings, DATA-xx contradictions, or locked-convention violations) → STOP. Route fix instructions to user for forwarding to the external consolidation agent. Phase 25 remains blocked until fix lands and re-check passes.

## Success Criteria

1. Every finding in the 19-row issue ledger maps to a resolution doc section (covered or partial; silent is a gap).
2. The verified-facts register shows no unexplained contradictions between the resolution doc and verified dataset facts.
3. The v1.4-locked convention check identifies zero violations (scope observations are recorded but are not violations).
4. The resolution-doc map provides enough information for Phase 25 to start evidence-packet construction without reading the full resolution doc first.
5. If any check fails, specific fix instructions are routed to the external consolidation agent, and Phase 25 remains blocked until the fix lands and re-check passes.

## Risk awareness

- **Consolidation not yet complete:** As of 2026-06-11, the 8 individual research results exist in `research_results/` and the consolidation input bundles are prepared in `consolidation_input/`, but the consolidated resolution doc has not yet been produced. This phase is gated on its arrival.
- **Individual vs consolidated doc:** If the user decides to use one of the individual research results as the resolution doc (e.g., the most comprehensive one) rather than waiting for consolidation, this phase verifies whichever doc is designated.
- **Scope observations are not violations:** The resolution doc may recommend changes to locked conventions. These are recorded as scope observations for user awareness, not treated as readiness failures.
