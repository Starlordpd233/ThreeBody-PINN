    **2. Data classes for parsed declarations**
    ```python
    @dataclass
    class PackageDecl:
        name: str           # e.g., "amsmath"
        options: str = ""   # e.g., "utf8" or "" (normalized: stripped whitespace)

    @dataclass
    class CommandDef:
        kind: str        # "newcommand", "renewcommand", "newenvironment", "DeclareMathOperator"
        name: str        # e.g., "\\vect", "authcommentenv", "\\median"
        full_text: str   # Complete definition text for comparison (whitespace-normalized)

    @dataclass
    class ConfigBlock:
        command: str     # e.g., "hypersetup", "lstset", "geometry", "lstdefinestyle", "definecolor", "setcitestyle", "usetikzlibrary"
        name: str = ""   # For named blocks like \lstdefinestyle{mystyle} or \definecolor{codegreen}
        content: str = "" # Full block content (whitespace-normalized)
    ```

    **3. `extract_preamble(content: str) -> str`**
    Extract everything between `\documentclass` (inclusive) and `\begin{document}` (exclusive). Use line-by-line scanning:
    - Find first line matching `r'^\s*\\documentclass'` -> start
    - Find first line matching `r'^\s*\\begin\{document\}'` -> end
    - Return `'\n'.join(lines[start:end])`
    - Return `''` if either marker not found

    **4. `resolve_preamble_inputs(content: str, base_dir: Path) -> str`**
    Resolve `\input{...}` directives within preamble content. This handles:
    - `\input{preamble_CTL}` in ctl-instruction
    - `\input{preamble}` in pinn-architecture, review_of_framework, stage_strat_revision
    - Data-quality-assessment has NO \input{preamble} (all inline) — no resolution needed
    Pattern: `r'^(\s*)\\input\{([^}]+)\}(.*)$'` per line. Add `.tex` if missing. Read the file, substitute its content. No recursion needed (preambles don't nest beyond one level).

    **5. `assemble_modular_preamble(main_path: Path) -> str`**
    Read main.tex content, resolve preamble inputs, then extract preamble. This is the composition:
    ```python
    content = main_path.read_text(encoding='utf-8')
    resolved = resolve_preamble_inputs(content, main_path.parent)
    return extract_preamble(resolved)
    ```

    **6. `parse_usepackage(preamble: str) -> list[PackageDecl]`** (per PREAMB-01, PREAMB-03)
    Regex: `r'\\usepackage(?:\[([^\]]*)\])?\{([^}]+)\}'`
    - Extract options (group 1, may be None) and package string (group 2)
    - Split package string on commas: `[p.strip() for p in pkg_str.split(',') if p.strip()]`
    - For comma-separated packages, ALL packages share the same options
    - Normalize options: strip leading/trailing whitespace
    - Return list of PackageDecl objects
    - MUST handle: `\usepackage{amsmath, amssymb, amsfonts}` -> 3 separate PackageDecl entries

    **7. `parse_command_defs(preamble: str) -> list[CommandDef]`** (per PREAMB-02)
    Must detect these patterns:
    - `\newcommand{\name}[nargs]{body}` — standard form with braces around name
    - `\renewcommand{\name}[nargs]{body}` — standard form
    - `\renewcommand\name{body}` — NO braces around name (ctl-instruction has `\renewcommand\theadfont{\bfseries}`)
    - `\newenvironment{name}{begin_def}{end_def}` — environment definitions
    - `\DeclareMathOperator{\name}{text}` — math operator declarations

    For `\newcommand`/`\renewcommand`:
    - Regex for both forms: `r'(\\(?:new|renew)command)\s*(\{\\[^}]+\}|\\[a-zA-Z]+)'`
    - This captures both `\renewcommand{\theadfont}` and `\renewcommand\theadfont`
    - After finding the command name, use brace-depth tracking to extract the full definition (including optional `[nargs]` and `{body}`)

    For `\newenvironment`:
    - Match `r'\\newenvironment\{([^}]+)\}'`
    - Use brace-depth tracking to extract the two `{begin_def}{end_def}` blocks

    For `\DeclareMathOperator`:
    - Match `r'\\DeclareMathOperator\{([^}]+)\}\{([^}]+)\}'`
    - Simple two-argument extraction

    For ALL types: store the full_text as the complete definition from the opening command to the final closing brace, with whitespace normalized (strip trailing whitespace per line, collapse blank lines).

    **8. `extract_braced_block(content: str, start_pos: int) -> tuple[str, int]`**
    Brace-depth tracking helper. Starting from start_pos, find the next `{`, track depth (increment on `{`, decrement on `}`), return the block content (including braces) and the position after the closing brace.

    **9. `parse_config_blocks(preamble: str) -> list[ConfigBlock]`** (per PREAMB-03)
    Detect and extract these configuration commands:
    - `\hypersetup{...}` — match `r'\\hypersetup\s*\{'`
    - `\geometry{...}` — match `r'\\geometry\s*\{'`
    - `\lstset{...}` — match `r'\\lstset\s*\{'`
    - `\lstdefinestyle{name}{...}` — match `r'\\lstdefinestyle\s*\{([^}]+)\}\s*\{'`, extract name
    - `\definecolor{name}{model}{spec}` — match `r'\\definecolor\s*\{([^}]+)\}\s*\{([^}]+)\}\s*\{([^}]+)\}'`, store name, full text
    - `\setcitestyle{...}` — match `r'\\setcitestyle\s*\{'`
    - `\usetikzlibrary{...}` — match `r'\\usetikzlibrary\s*\{'`

    For blocks with braces (`\hypersetup`, `\geometry`, `\lstset`, `\lstdefinestyle`, `\setcitestyle`): use `extract_braced_block` to handle multi-line content. Normalize content: strip trailing whitespace per line, collapse multiple spaces to single space within values.

    **10. `parse_documentclass(preamble: str) -> str`**
    Extract the full `\documentclass` line for informational comparison.
    Regex: `r'\\documentclass(?:\[([^\]]*)\])?\{([^}]+)\}'`
    Return the full matched string (e.g., `\documentclass[11pt, a4paper]{article}`).

    **11. Comparison functions**

    `compare_packages(original: list[PackageDecl], modular: list[PackageDecl]) -> dict`:
    - Build dict by name for both sides
    - `matched`: packages in both with identical options
    - `missing`: packages in original but not in modular
    - `extra`: packages in modular but not in original
    - `option_mismatches`: packages in both but with different options (show both sides)
    - Return dict with these 4 lists

    `compare_commands(original: list[CommandDef], modular: list[CommandDef]) -> dict`:
    - Build dict by `(kind, name)` tuple for both sides
    - `matched`: same kind+name+full_text
    - `missing`: in original but not in modular
    - `extra`: in modular but not in original
    - `body_mismatches`: same kind+name but different full_text (show both sides)
    - Return dict with these 4 lists

    `compare_config_blocks(original: list[ConfigBlock], modular: list[ConfigBlock]) -> dict`:
    - Build dict by `(command, name)` tuple for both sides
    - `matched`: same command+name+content
    - `missing`: in original but not modular
    - `extra`: in modular but not original
    - `content_mismatches`: same command+name but different content — use `difflib.unified_diff` for side-by-side comparison of the normalized content
    - Return dict with these 4 lists

    **12. `verify_structure(structure: PreambleStructure, base_path: Path, verbose: bool = False) -> dict`**
    Orchestrate verification for one structure:
    1. Read original, extract preamble via `extract_preamble()`
    2. Assemble modular preamble via `assemble_modular_preamble()`
    3. Parse both preambles: `parse_usepackage()`, `parse_command_defs()`, `parse_config_blocks()`, `parse_documentclass()`
    4. Compare: `compare_packages()`, `compare_commands()`, `compare_config_blocks()`
    5. Compare documentclass strings
    6. Determine pass/fail: PASS if no missing, no extra, no option_mismatches, no body_mismatches, no content_mismatches in any category
    7. Return dict with all results
