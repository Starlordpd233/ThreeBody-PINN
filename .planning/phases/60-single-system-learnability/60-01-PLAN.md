<objective>
Build the learnability harness's thinnest real path first: one data-only arm on a tiny
fixture corpus, read through the train/validation allowlist, normalized like the trainer
normalizes it, trained by the production network with the trainer's own loss, polished by
the frozen L-BFGS rule, scored on both states, recorded exactly once, and refused by the
evaluator. Then install the Phase 60 static guard that every later plan reruns.

In plain language: before any real experiment runs, this plan proves that the tool can
train one orbit, score it in physical units, and save exactly one result that the
evaluator will not accept as a graded run. It also adds the automatic checks that keep
every later piece of the tool from loading files unsafely or hiding an owner stop.

Purpose: SPEC Requirement 2 (harness core), INST-05 (d) and the base half of (c); D-04
(data-only arms use the Stage-0 cosine), D-10 and GAP-60-08 (plain-git weights), GAP-60-05
(polish semantics), GAP-60-13 (normalizer). Plan 60-23 closes the refusal contracts that
need no physics: the closed arm catalog with the override refusal (INST-05(e)), the
override half of (c), and the test-split refusal with the record preflight (INST-05(b),
SPEC Requirement 8). Physics terms are Plan 60-05; the frozen budget rule, timing run and
extension are Plan 60-08. This plan is the only Wave-1 plan: it creates the tests/phase60
package, and Plans 60-02 and 60-03 run after it (60-02 edits the scorer this plan's tests
call).

Output: four pinn/verification modules (Phase 60 docstring marker), the tests/phase60
package and its fixture helpers, and two test modules.
</objective>
