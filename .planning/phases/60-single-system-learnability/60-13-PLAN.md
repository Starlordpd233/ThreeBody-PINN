## The g2 tokens and what final requires

`verify_phase60_evidence.py g2 --require NAMES` takes NAMES as one comma-separated list. Each token names exactly one file under `evidence/g2/`: the file Plan 60-06's writer creates and the consumer plan commits.

| Token | File under evidence/g2/ | Schema | Plan 60-06 writer | Required by |
|-------|-------------------------|--------|-------------------|-------------|
| outcome | g2-outcome.json | phase60-g2-outcome/v1 | learnability_g2 outcome | Plans 60-14, 60-15, 60-16 and 60-18; final (Plan 60-22) on every path |
| sweep-curve | sweep-curve.json | phase60-sweep-curve/v1 | learnability_g2 sweep-curve | Plans 60-15 and 60-16; final when G2 fired |
| rescue | rescue.json | phase60-rescue/v1 | learnability_g2 rescue | Plan 60-16; final when the confirmation ran |
| skip-records | skip-records.json | phase60-skip-records/v1 | learnability_g2 skip --reason | Plan 60-18; final on a stop at G2 |
| stop-handoff | stop-handoff.json | phase60-stop-handoff/v1 | learnability_g2 stop-handoff | Plan 60-18; final on a stop at G2 |

Token rule (fail-closed). NAMES is split on commas, and each element must equal one of the five tokens exactly: no whitespace stripping, no case folding, and no fallback that turns an unknown name into a file name. An unknown token, a repeated token, an empty value or an empty element is refused before any file is read: FAIL-CLOSED naming the token, exit 1, no G2-OK. A named file that is missing, is not JSON, carries another schema, or differs from its recomputation (the g2 checks in must_haves) fails the same way, naming the file. Every g2 file that is present is checked whether or not it is named; --require only adds that the named files must exist. G2-OK prints only when every check passes.

No --require, and final. With no --require, g2 requires exactly the g2 files the recorded path implies, and final runs g2 that way. It fails, naming the file, on a missing implied file or on any present g2 file the path does not imply. The path is read from the committed g2 files, the run protocol's g2.failed_confirmation_pre_answer, and the two owner rulings (through learnability_ruling's loaders):

| Recorded path | Files required | Files that must be absent |
|---------------|----------------|---------------------------|
| G2 did not fire (g2-outcome.json g2_fired false) | g2-outcome.json | the other four |
| G2 fired and no sweep setting reached Tier 1 (sweep-curve.json outcome no_rescue) | g2-outcome.json, sweep-curve.json, skip-records.json, stop-handoff.json | rescue.json |
| G2 fired, the confirmation ran (sweep-curve.json outcome confirmation_pending), and the stop was reached: rescue.json records failed_confirmation with the protocol's pre-answer no_rescue or a GAP-60-09 ruling reading no_rescue, or the checkpoint ④ ruling answers go-to-verdict | all five | none |
| G2 fired, the confirmation ran, and the checkpoint ④ ruling answers continue | g2-outcome.json, sweep-curve.json, rescue.json | skip-records.json, stop-handoff.json |
| Not yet decidable: a deciding file is missing, a failed confirmation has neither a pre-answer nor a GAP-60-09 ruling, or a rescue (rescue.json outcome rescue, or a failed confirmation read as rescue) has no checkpoint ④ ruling | none; g2 fails closed, naming what is missing | none |
