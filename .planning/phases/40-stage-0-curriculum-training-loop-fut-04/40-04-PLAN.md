## ⛔ OPEN DECISION — BLOCKS Task 1 (and 40-05 Task 2 / 40-06 Task 1). DO NOT INVENT.

Two cross-AI review findings (cycle 2) resolve to **one** ungrounded design decision.

Full record: `.planning/phases/40-stage-0-curriculum-training-loop-fut-04/40-GAPS.md`
(**GAP-40-01**, **GAP-40-02**); index: `.planning/milestones/v2.0-GAPS.md`. Status: **OPEN**.

### What IS grounded (transcribe this; do not re-litigate)

- `ctl_instruction.md:1928` — "the training loop's stage-exit decision is an operational
  state machine with **three dispositions: ADVANCE, RECOVER, and HALT/REVIEW**."
  REQUIREMENTS TRAIN-06 and 40-SPEC R6 list the same three.
  ⇒ **The three-member `StageDisposition` enum is CORRECT and stays.** The cycle-2
  reviewer's suggested fix ("add a fourth `CONTINUE` member") would CONTRADICT this
  locked source by minting a fourth *disposition*, and is therefore NOT adopted.
- `ctl_instruction.md` CURR-03 — ADVANCE only on the four-criterion gate; MAX_EPOCHS /
  stagnation / NaN-Inf are explicitly REJECTED as advancement triggers and route to
  HALT/REVIEW or RECOVER. No fallback advancement. This behavior is fully specified.

### What is NOT grounded (the actual gap)

**GAP-40-01 — how the machine represents "no exit disposition fired at this poll."**
The spec fixes the three *exit* dispositions but is silent on the return value when the
stage is mid-flight: gate not yet passing, no NaN, budget not exhausted. That state is
real (criterion 1 compares `L_smooth(i)` to `L_smooth(i−patience)` at epoch `i`, and HALT
is defined as *reaching* max-epoch "without satisfying the gate" — both presuppose polls
that fire nothing). `grep` for `CONTINUE` / "continue training" across ctl_instruction.md,
REQUIREMENTS.md, 40-CONTEXT.md, and 40-SPEC.md returns **zero hits**.

**GAP-40-02 — the relationship between `MAX_EPOCHS` and `N_Adam,k`.**
Both are CTX-39/CTX-48 config-required, owner-picked. `N_{Adam,k}` appears in exactly one
place in the corpus — `pinn_architecture.md:660`, as an input to the warmup formula
`I_warm = min(2000, 0.1·N_Adam,k)` — and is never defined or related to `MAX_EPOCHS`.
`ctl_instruction.md` marks the per-stage `MAX_EPOCHS` table itself claimed-unverified
(D5-05; CLM-08/09), not transcribed as locked. Nothing states whether MAX_EPOCHS bounds
the whole stage (Adam + L-BFGS) or the Adam phase alone. 40-05's descending-curve
acceptance criterion ("exits Adam at N_Adam,k ⇒ HALT/REVIEW") is only provable under
`N_Adam,k ≥ MAX_EPOCHS`; under the other reading the stage lands in GAP-40-01's
unrepresented state instead. **This is why the two are one decision.**

### Options for the owner

| # | GAP-40-01 representation | Consequence |
|---|---|---|
| **A** | Add a 4th `CONTINUE` member to `StageDisposition`. | Simple `match`, but contradicts `ctl_instruction.md:1928` ("three dispositions") and lets a caller mistake CONTINUE for a terminal exit decision. |
| **B** *(recommended)* | `StageExitOutcome.disposition: StageDisposition \| None`; `None` = no exit decision fired, keep training. | Keeps the locked three-member set intact; the type system forces every caller to handle the not-exiting case explicitly; "no disposition" is representationally honest — it is the ABSENCE of an exit decision, not a fourth kind of one. |
| **C** | Separate boolean (`should_exit` + `disposition`). | Two fields can disagree (`should_exit=False` with `disposition=ADVANCE`); an invalid state is representable. Weakest of the three. |

| # | GAP-40-02 epoch-budget relationship | Consequence |
|---|---|---|
| **A** *(recommended)* | `MAX_EPOCHS` bounds the WHOLE stage (Adam + L-BFGS); `TrainingConfig` validates `N_Adam,k ≤ MAX_EPOCHS` at construction. | Matches the plain reading of "per-stage max-epoch budget". Needs a stated rule for "Adam budget exhausted, no plateau, stage budget remains". |
| **B** | `N_Adam,k ≥ MAX_EPOCHS` (Adam budget ≥ stage budget), making Adam exhaustion == max-epoch. | Makes 40-05's descending-curve → HALT criterion provable as written, but reads MAX_EPOCHS as an Adam-phase bound, which the spec does not say. |
| **C** | Independent budgets; exhausting `N_Adam,k` without a plateau handoff is itself a stagnation trigger → HALT/REVIEW. | Uses the spec's existing stagnation → HALT path; requires calling exhaustion "stagnation", which the spec does not define. |

**Planner recommendation: GAP-40-01 → B, GAP-40-02 → A.** Both are *representation /
budget-bookkeeping* choices with no effect on the locked science (the gate, its four
criteria, and "no fallback advancement" are unchanged under every option). They are
surfaced rather than auto-resolved because GAP-40-01 touches the load-bearing
no-fallback-advancement safety contract and GAP-40-02 changes which terminal state a real
run reaches — neither is a mechanical/presentation call the 2026-07-16 autonomy directive
covers.
