<objective>
Complete the ERW Rule-19 verification report: triage every anchor the closed-book
report cites, give every claim in it a verdict, and record which agreements
between the two reports are corroboration and which are not.

Purpose: the round declared one access mode and one engagement did not run under
it. That engagement's report carries repository anchors it never resolved against
the repository — honestly labelled as package-derived by its own author, and
still, in citation form, indistinguishable at a glance from anchors that were
resolved. Two failures follow if this half is skipped. A reconstructed anchor
that happens to be wrong would be read as a repository fact. And the two reports
agreeing on a repository fact would be read as two confirmations when only one of
them could look.

Output: the anchor-provenance triage, the closed-book claim ledger, the
cross-report independence ledger with its per-row entitlement verdict, and the
report's closing sections. After this plan the verification report is complete
and the premise adjudication in wave 4 may begin.

Per D-12 this half extends the same file the previous half created, and per D-14
it applies the claim-class independence taxonomy rather than re-deriving it.
</objective>

burdens, and fixed the four-class independence taxonomy. `54-09` created the

**Tracer note.** This phase's tracer is `54-01`. `54-10` is an expansion plan on
that proven shape; no new tracer is emitted.

**Why this half exists at all.** The runbook's access-mode table sets the
receiving-end burden for a closed-book round at none beyond normal channel
protocol. That line assumes a closed-book package built under Rules 1 and 2,
where repository paths are forbidden in the uploads precisely so that a
closed-book agent cannot cite what it cannot see. This round inverted those rules
because it was built as an open-book round, so its attachments are full of
repository anchors — and the engagement that ran without repository access
inherited them. The runbook anticipates neither case, so the burden is derived in
`54-INTAKE.md` and discharged here.

**Neutrality standing.** As in wave 2: verifying a claim about a decision surface
is not disposing of that surface, and this plan performs only the first. Bar G is
inherited byte-unchanged with its file list extended, as `54-08-PLAN.md` records.

<edge_dispositions>
## Deterministic edge probe — the rows this plan discharges

| # | Category | How it binds here |
|---|---|---|
| E1 | boundary | An anchor citing a line at the exact first or last line of a verbatim block is **inside** that block. The triage's range test is inclusive at both ends, stated as inclusive in the report, and an off-by-one at a boundary would misclassify a legitimate reconstruction as untraceable. |
| E2 | region non-emptiness | Every extraction prints its region size before its verdict, and the derived anchor total is required greater than zero, so a silently-empty extraction cannot pass a coverage check by making both sides zero. |
| E3 | duplication | An anchor cited many times is one triage row. The distinct set is taken under `LC_ALL=C` and the occurrence count is recorded inside the row. |
| E5 | conflict | Where the two reports state the same thing differently, both statements are recorded in their authors' own terms and the row's disposition addresses the difference. Averaging is not available as a disposition. |
| E6 | empty | A bucket that legitimately holds nothing is recorded as holding nothing, with its count printed, rather than omitted. An omitted bucket and an empty bucket are different findings. |
| E7 | ordering | Anchors are triaged in sorted order under `LC_ALL=C`; ledger rows follow the source report's own order. |
</edge_dispositions>

**Build the cross-report independence ledger.** Open it with the marker
`INDEPENDENCE-LEDGER` and close it with `END-INDEPENDENCE-LEDGER` on its own
line immediately after the last data row. The gate counts rows and entitlements
between the two markers and requires every row inside them to carry an
entitlement, so an unbounded ledger would sweep in every table that follows and
report their cells as ledger rows. One row per point on which both
reports say something about the same question. Columns:
`Point | What report one says, in its own terms | What report two says, in its own terms | Claim class | Entitlement | Disposition | Note`.

Fill it as follows:

- **Point.** The question, stated once, neutrally, without either report's framing.
- **The two positions.** Each in its author's own terms with its citation. Do not
  paraphrase into a common vocabulary; a paraphrase is where a difference
  disappears.
- **Claim class.** One of the four classes `54-INTAKE.md` fixed.
- **Entitlement.** A verdict from a closed pair, determined by the class and not
  by how convincing the agreement looks:
  - `CORROBORATED` — the class admits independent corroboration and both reports
    reached the point from evidence each could actually see.
  - `NOT-CORROBORATED` — the class does not admit it. Every row in this bucket
    states why in its own text, and for repository-derived points states that the
    matching statement from the engagement that read no tree is evidence about
    attachment fidelity rather than a second reading.
  A row must carry one of the two and nothing else. Where an agreement is on an
  analytic point both reports derived from the same package premise, the
  entitlement is `NOT-CORROBORATED` with the shared premise named — the premise
  is what would have to be wrong, and both agents inherited it from the same
  place.
- **Disposition.** For rows where the two positions differ, a value from a closed
  set: `RESOLVED-BY-EVIDENCE` (a ledger verdict settles it — name the verdict),
  `RECONCILABLE` (the two statements are compatible once a qualifier both reports
  state is applied — name the qualifier), `OPEN-DISPUTE` (they are incompatible
  and no verdict in this report settles it), or `OUT-OF-SCOPE-HERE` (settleable
  only by evidence this milestone's scope rows put behind an owner decision —
  name what would settle it). For rows where the positions agree, the disposition
  is the entitlement's consequence and is stated as such.

**Averaging is not available.** There is no disposition meaning "somewhere in
between", and a disagreement is never resolved in favour of the engagement that
read the tree merely because it read the tree. Repository access settles
repository questions; it settles no question of arithmetic, of literature, or of
what the package's own text says. State that rule in the ledger's preamble.

**Flag the physics-dispute class explicitly.** The delivery note's join points
state that two agents disagreeing about a scaling law have a dispute that must be
settled before the menus downstream of it are trusted, while two agents
disagreeing about a marked default while agreeing on the scaling laws have a
resolvable disagreement. Apply that distinction here rather than in the
consolidation: for every point that is a statement about how a quantity scales,
record whether the two reports agree, and where they do not, mark the row
`OPEN-DISPUTE` and add a sentence naming the menus that sit downstream of it.
This is the single most consequential output of this ledger and it is why the
ledger comes before the consolidation rather than inside it.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a relayed anchor -> a repository fact | An anchor the agent was handed carries the package's accuracy, not the agent's. Reading it as the agent's finding credits a check nobody ran. |
| a reconstructed anchor -> the line it names | Computing a line from an offset inside a supplied block is legitimate and is also where an off-by-one lands invisibly, because the resulting citation looks exactly like a resolved one. |
| two agreeing reports -> two confirmations | The entitlement question is decided by the claim's class. Deciding it by how convincing the agreement looks is the failure this ledger exists to prevent. |
| a disagreement -> an average | Averaging two positions produces a third that neither author holds and that no evidence supports, and it destroys the finding the disagreement was. |
| repository access -> authority on every question | Reading the tree settles questions about the tree. It settles nothing about arithmetic, literature, or what the package's own text says. |
