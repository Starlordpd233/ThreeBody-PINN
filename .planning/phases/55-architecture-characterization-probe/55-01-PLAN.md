<derived_facts>
## Norm convention — derived, not assumed

The audit's §6b table does not state which norm its `‖·‖` columns use. It is
recoverable by arithmetic from the table itself plus the locked `R̄` contract
`rbar = (residual ** 2).sum(dim=(-2, -1)) / 3.0`
(`pinn/training/controllers.py:652-656`).

`‖F_grav‖` is 2.17–5.94 while `‖a′‖` is ~2e5, so `residual = accel - force ≈
accel` to five significant figures. If `‖·‖` is the plain Frobenius norm over
the nine scalar components of the (3 bodies × 3 Cartesian) tensor, then
`R̄ = ‖a′‖² / 3`. Checking every row of the audit table:

| ‖a′‖ | ‖a′‖²/3 | audit R̄ |
|---|---|---|
| 2.03e5 | 1.373e10 | 1.37e10 |
| 2.72e5 | 2.466e10 | 2.46e10 |
| 2.20e5 | 1.613e10 | 1.62e10 |
| 2.79e5 | 2.595e10 | 2.60e10 |
| 1.94e5 | 1.255e10 | 1.25e10 |
| 2.28e5 | 1.733e10 | 1.74e10 |

All six agree to three significant figures. The RMS-body-norm alternative
(`sqrt((x**2).sum(dim=(-2,-1)) / 3)`) would be off by exactly a factor of 3 in
`R̄` and is therefore ruled out. **Use the plain Frobenius norm over the flattened
nine components per collocation point for all four norm columns.** Task 2 turns
this into a live acceptance criterion rather than a comment.

## Median convention — a documented discretion choice

`n_col = 16` is even, so "median" is under-determined: `numpy.median` averages
the two central order statistics, `torch.median` returns the lower of the two.
CONTEXT.md places this in Claude's discretion and requires the choice be
documented in the module docstring and the provenance output. **This phase uses
`numpy.median`** (the standard statistical definition). The three-significant-
figure agreement above is consistent with either convention, so this is a
documentation obligation, not a physics adjudication.
</derived_facts>
