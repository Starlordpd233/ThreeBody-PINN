<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| checkpoint file → torch.load | A checkpoint's bytes are untrusted (could be truncated/corrupt or, in principle, a malicious pickle); the store must not execute arbitrary code on load and must not resume from a wrong-schema file. |
| in-flight write → readers | A concurrent fallback-scan read of an in-flight write must never observe a partial file. |
| checkpoint accumulation → disk | Unbounded checkpoint growth is a self-inflicted disk-exhaustion (DoS) risk. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-41-05 | Tampering / Elevation of Privilege | torch.load on checkpoint bytes (main load, fallback scan, rollback) | high | mitigate | `weights_only=True` at EVERY load site; no `weights_only=False` escape hatch; payload is a plain CTX-53 dict (no custom pickled classes).
