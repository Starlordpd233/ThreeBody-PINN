<objective>
Finish the Phase 66 harness so the real runs can be launched, read and budgeted mechanically, then freeze it (D-07, D-08, D-09, D-10).

In plain language: this plan finishes three small tools.
- **The power gate.** It refuses on any power reading it does not fully understand, refuses outside the owner's weekend window (the owner's words: the Mac is plugged in "for the weekend only. not weekdays"), and refuses to reuse a run folder.
- **The reading rule.** It turns a run's score into one of five labels: Tier 1; near the constant predictor; between the two; other; or unsettled. "Unsettled" means the run missed Tier 1 while its output was still learning to move with time when its steps ran out, so its score is not final; such a run always goes to the owner. The rule also checks that the run really tested the registered network on the registered orbit, and decides whether the three runs agree. A separate mechanics-only check lets the timing run be verified without anyone seeing its score.
- **The budget calculator.** It turns the timing run's measured speed into a step count. Time is the only limit: the run must stay safely under the one-hour cap. The record stays small enough to commit at any length (the repository refuses committed files over 10 MiB), because the loss trace keeps at most 10,001 entries and the similarity log at most 14.

After this plan the code is frozen: the pages and registrations written next pin these exact bytes.

Purpose: success criteria SC-1 and SC-2 need a reading rule that is unambiguous at its edges and a budget from the measured rate. Both are tested before any real run exists, so neither can be shaped by a result (SCOPE-47).
Output: extended `diagnostic_power.py` and `diagnostic_phase66.py`, and `tests/phase66/test_power.py`, `test_reading_rule.py`, `test_budget.py` and `test_pages.py`.
</objective>
