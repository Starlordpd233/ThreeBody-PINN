Purpose: This is the only honest pass/fail for the whole milestone. The gate metric (eps_H/SCS from model predictions) is the single genuinely-new piece of logic in Phase 43; everything else is orchestration.
Output: `pinn/verification/gate_metrics.py`, `pinn/evaluate.py`, and three test modules (gate boundary, gate render, edge cases).

**⚠ FLAGGED OWNER-CONFIRMATION ITEM (do not bury):** `43-SPEC.md`'s SCS wording ("PASS if SCS > -5", "SCS == -5 -> FAIL", "OVERALL FAIL iff ... SCS <= -5") is **backwards** and internally self-contradictory: since `SCS = log10(eps_H)` is monotonic, `eps_H > 1e-5` and `SCS > -5` are the SAME event and cannot have opposite verdicts, yet SPEC.md assigns `eps_H==1e-5 -> PASS` and `SCS==-5 -> FAIL` to that one point in adjacent bullets. This plan builds the gate and its negative test to the AUTHORITATIVE direction (REJECT iff `eps_H > 1e-5`; boundary `eps_H==1e-5` == `SCS==-5` -> PASS), grounded in `ctl_instruction.md` §5:567-568 and `data_quality_assessment.md` §3.1:120,130 and the ratified trainex-r1a finding B-8. **The owner must correct the SPEC's SCS boundary wording before the ACC-06 acceptance verdict (plan 43-08) is rendered.** This is a grounded technical decision under owner delegation, recorded here as an explicit documented deviation — NOT a silent application of the SPEC's literal text.
</objective>
