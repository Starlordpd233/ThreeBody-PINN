## GAP-18-01: AC-FRAME acceptance-check naming (new names beyond Phase 16 reservation)

- **Decision point:** Phase 16's `16-ISSUE-LEDGER.md` reserves exactly one Phase 18 acceptance-check name — `AC-FRAME-01` — bound to findings B-05 and M3. Phase 18 has four requirements (FRAME-01..04). Should Phase 18 reserve additional `AC-FRAME-*` names, and if so how many?
- **Where in artifact:** `18-CONTEXT.md` §"Implementation Decisions" D-08.
- **Task context:** Analyzing Phase 18's acceptance-check structure during `gsd-discuss-phase 18` (Area 3 of the grey-area discussion). Hit this gap when mapping the four FRAME requirements onto the ledger's single reserved AC name.
- **Classification:** process-artifact schema.
- **Source silence:**
  - `.planning/phases/16-evidence-framework-and-issue-adjudication/16-ISSUE-LEDGER.md` — reserves `AC-FRAME-01` for B-05 and M3 only; FRAME-02/03/04 are *requirements*, not *findings*, and the ledger maps findings→ACs, so it neither reserves nor forbids `AC-FRAME-02/03/04`.
  - `.planning/phases/16-evidence-framework-and-issue-adjudication/16-CONTEXT.md` D-13/D-14 — naming policy `AC-{REQ-ID}[-{NN}]`; "multiple findings may share an AC-ID"; pass criteria deferred to Phase 21. Does not state how many AC names a phase reserves for requirements without dedicated findings.
  - `.planning/REQUIREMENTS.md` VER-01 — Phase 21 defines acceptance checks for "scaling consistency, COM invariance, derivative correctness, force-energy consistency, loss stability" but does not enumerate `AC-FRAME-*` names.
- **Mathematical / engineering grounding:** Acceptance-check names are the index Phase 21's VER-04 uses to know which disposable probes to execute. The structural choice has concrete downstream consequences: (a) if Phase 18 reserves only `AC-FRAME-01`, then FRAME-02's numeric COM-invariance probe (Phase 21 §10.2, tolerance `1e-12`), FRAME-03's sampling-frame reconciliation check, and FRAME-04's output-shape check all share one name — Phase 21 cannot cite a per-requirement pass/fail in the ledger without inventing names at execution time, and inventing AC names in Phase 21 would itself be a governance gap *in Phase 21*; (b) reserving `AC-FRAME-01..04` (one per requirement) gives Phase 21 a complete, collision-free index and matches the precedent Phase 17 set with `AC-IO-01..04` (where the requirement-level `AC-IO-04` was itself a reserved-with-instruction addition, GAP-17-02). The reservation is cheap and reversible; the cost of under-reserving is pushed onto Phase 21 as a forced late invention. This is a process-artifact schema decision, not a physics decision — but governance explicitly lists "new AC names beyond Phase 16 reservations" as MUST-surface.
- **Agent was tempted to:** Reserve `AC-FRAME-01..04`, one per FRAME requirement, on Phase-17-parallelism reasoning.
- **What the user needs to decide:**
  - (a) Reserve `AC-FRAME-01..04`, one per requirement (AC-FRAME-01 = B-05+M3 preprocessing order; 02 = COM/momentum assertions; 03 = sampling-frame reconciliation; 04 = 3D-Cartesian output).
  - (b) Reserve `AC-FRAME-01` + one new `AC-FRAME-02` for the numeric COM/momentum check only; fold FRAME-03/04 under AC-FRAME-01.
  - (c) Keep only `AC-FRAME-01`; verify FRAME-01..04 via that one AC plus ROADMAP success criteria.

- **Documents to review** (Option A — simple list, process-artifact gap):
