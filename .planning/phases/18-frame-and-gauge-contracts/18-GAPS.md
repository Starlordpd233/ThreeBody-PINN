## GAP-18-04: Rotation-gauge epsilon threshold values

- **Decision point:** The canonical rotation-gauge algorithm uses threshold guards `epsilon_rho` and `epsilon_lambda` for degenerate Jacobi geometry, but Phase 18 sources do not bind their numerical values or whether they are absolute, scaled, or relative thresholds.
- **Where in artifact:** `18-01-PLAN.md` Task 2 sub-step 2.4 (`Canonical rotation gauge`) and any eventual `ctl_instruction.md` Step 2.4 rotation-gauge text.
- **Task context:** Optimizing Phase 18 plans against `docs/findings/fixing_gaps/2026-05-20-phase-18-plan-review.md`; the review found the plan omitted the rotation-gauge construction body and that the resolution document's epsilon symbols are unbound.

- **Source silence:**

  - `pinn_instruction/markdown_conversion/framework-revisions/research_reports/01-architecture-and-physics-foundations/ctl_pinn_resolution.md:348` — uses `||lambda_perp|| > epsilon_lambda` but does not define `epsilon_lambda`.
  - `pinn_instruction/markdown_conversion/framework-revisions/research_reports/01-architecture-and-physics-foundations/ctl_pinn_resolution.md:354-370` — specifies the collinear fallback sequence but does not state the threshold used to classify projected candidates as nonzero.
  - `pinn_instruction/issues/01-architecture-and-physics-foundations.md` — discusses softening/invariant epsilons, but not rotation-gauge degeneracy thresholds.
  - `.planning/REQUIREMENTS.md` FRAME-01/FRAME-04 and `.planning/ROADMAP.md` Phase 18 success criteria — require frame/gauge and 3D Cartesian preservation, but do not bind gauge-degeneracy tolerances.
- **Mathematical / engineering grounding:** `epsilon_rho` decides when the primary Jacobi vector is too close to zero to define the x-axis robustly. `epsilon_lambda` decides when the second Jacobi vector has enough component perpendicular to `e_x` to define the y-axis instead of using the collinear fallback. These values are not cosmetic: if too small, numerical noise near collisions or collinear cases can create unstable rotations; if too large, valid near-collinear geometries may be routed through the fallback and lose continuity with the generic gauge. Absolute raw-coordinate thresholds, scaled-coordinate thresholds, and relative thresholds have different downstream behavior because Phase 18 applies COM/boost before scaling and then stores both gauge and scale metadata.
- **Agent was tempted to:** Transcribe the algorithm symbolically with `epsilon_rho` and `epsilon_lambda`, leave numerical binding to FUT-01/Phase 21, and add a STOP guard so no executor invents numeric values during Phase 18.
- **What the user needs to decide:**
  - (a) Keep `epsilon_rho` and `epsilon_lambda` symbolic in Phase 18, explicitly defer numerical binding to Phase 21 acceptance-check design or FUT-01 implementation.
  - (b) Provide exact numerical values now and specify whether they are raw-coordinate, scaled-coordinate, or relative thresholds.
  - (c) Define a dimensionless relative-threshold contract now, for example comparing `||rho||/D` and `||lambda_perp||/D` against named tolerances, with exact values supplied by the user.
  - (d) User writes the exact threshold contract directly.
- **Confidence of impact:** **HIGH** — affects implementability and numerical stability of the canonical rotation gauge, and the governance block explicitly treats source-silent semantic choices as MUST-surface.
- **Status:** **RESOLVED-WITH-INSTRUCTION**
- **Resolution note:** User approved option (c) on 2026-05-21 with the exact binding documented in `docs/findings/fixing_gaps/closing_18-04_gap.md`. Define `η_gauge = 1e-8` as the single dimensionless rotation-gauge degeneracy tolerance. Because Phase 18's canonical rotation is applied AFTER COM recenter + zero-momentum boost + canonical ordering but BEFORE global scaling, the raw-space guards are `ε_ρ = η_gauge · D` and `ε_λ = η_gauge · D`; the fallback velocity-candidate guard is `ε_v = η_gauge · V`, `V = D/T`. Equivalently, implementations may compare the dimensionless ratios `‖ρ‖/D`, `‖λ_⊥‖/D`, and `‖c_⊥‖/V` against `η_gauge`. If `‖ρ‖/D ≤ η_gauge` the trajectory is classified as `gauge_degenerate_ρ` and rejected or quarantined per the §4.1 mass-invariance failure-handling pattern — the executor does NOT invent an arbitrary `e_x` axis. After selecting `e_y` in the fallback branch, the sign convention `if λ_⊥·e_y < 0 → e_y ← −e_y` enforces `λ_y ≥ 0` deterministically. `η_gauge` is a numerical geometry guard for stable rotation-matrix construction; it is NOT a physics softening parameter and is NOT tied to `ε_train` or `ε_inv`. Numeric acceptance-check pass criteria for `AC-FRAME-*` remain Phase 21 VER-01/VER-04 scope per GAP-18-03 (the branch-aware test-tolerance note inside `closing_18-04_gap.md` is informational guidance for Phase 21, not a Phase 18 spec or `AC-FRAME-*` criterion).
