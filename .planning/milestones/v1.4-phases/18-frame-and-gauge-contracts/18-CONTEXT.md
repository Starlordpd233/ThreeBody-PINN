### Verdicts (grounded — both findings uncontested)

- **D-01 (B-05 verdict — COM frame consistency; B-11 folded in):** `accept-resolution`. The resolution doc (`ctl_pinn_resolution.md` §4.2, lines 271-304) and the issue doc ("Frame Convention: Galilean Boost Mandate", lines 237-253) **agree**: apply a universal COM recenter + zero-momentum boost to ALL datasets — hierarchical and quasi-random — regardless of whether they are believed to already be in COM frame. `16-ISSUE-LEDGER.md` confirms `Sources Disagree? = NO`. No EVID-05 adjudication. B-11 (COM ↔ mass consistency) is folded into B-05 per the ledger; the unified pipeline's mass-invariance check (`max|mᵢ(t)−mᵢ(0)| < 1e-15`, resolution doc §4.1) carries the B-11 mass-consistency assertion.
  - **Why:** Training on mixed-frame data (hierarchical ICs perturbed out of COM frame, quasi-random ICs in COM frame) makes the network spend capacity learning linear coordinate transforms instead of gravitational dynamics (issue doc line 241). A universal transform removes the artifact deterministically.
  - **How to apply:** Evidence packet `evidence/B-05.md` records the uncontested verdict; §5/7/8/9 (EVID-05 sections) carry `Not contested` markers per the Phase 17 non-EVID-05 pattern.

Both sources agree: **COM transform FIRST, then scale** (resolution doc §4.5 line 405-416; issue doc M3 row line 85, "COM transform FIRST, then scale"). Global scaling commutes algebraically with COM subtraction, but a non-zero COM that survives into a scaled file is a mixed-frame artifact; the documented order is required for auditability and to avoid mixed-frame intermediate files (resolution doc line 416). `Sources Disagree? = NO`.

### Rotation-gauge degeneracy thresholds (GAP-18-04 closure)

- **D-14 (rotation-gauge degeneracy thresholds — LOCKED 2026-05-21):** Bind `η_gauge = 10⁻⁸` as the single dimensionless rotation-gauge degeneracy tolerance. Because Phase 18's canonical rotation runs AFTER COM recenter + zero-momentum boost + canonical ordering but BEFORE global scaling, define `ε_ρ = η_gauge · D`, `ε_λ = η_gauge · D`, and (for fallback velocity candidates) `ε_v = η_gauge · V` with `V = D / T`. Implementations may equivalently compare `‖ρ‖/D`, `‖λ_⊥‖/D`, and `‖c_⊥‖/V` against `η_gauge`. If `‖ρ‖/D ≤ η_gauge` the trajectory is classified `gauge_degenerate_ρ` and rejected or quarantined per the §4.1 mass-invariance failure pattern (no arbitrary `e_x` axis). In the fallback branch, after selecting `e_y` from the first admissible velocity-candidate projection, apply the deterministic sign convention `if λ_⊥·e_y < 0 → e_y ← −e_y` to honor the `λ_y ≥ 0` gauge target. `η_gauge` is a numerical geometry guard for rotation-matrix construction — NOT a physics softening parameter, NOT tied to `ε_train` or `ε_inv`. Numeric `AC-FRAME-*` acceptance-check criteria remain Phase 21 VER-01/VER-04 scope (GAP-18-03). Grounded by user instruction 2026-05-21 (RESOLVED-WITH-INSTRUCTION on GAP-18-04); rationale and validation guidance live in `closing_18-04_gap.md`.
