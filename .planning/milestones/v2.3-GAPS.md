- **GAP-57-02** — RESOLVED-WITH-INSTRUCTION (owner-delegated, 2026-09-09). The ratified 4096-row recipe exceeds this
  machine's memory and throughput. Band generation 1 halted on the Tier-2
  `memory_watermark` guard at stage 0 / step 0 / phase `2a`, before any
  optimizer update; evaluation preserved-unspent, non-terminal. Diagnosis:
  the guard reads the allocator's reserved high-water pool
  (`driver_bytes` = 23.25 GiB) while live tensors are 8.8 MiB, so the pressure
  is a transient in-step peak from a second-order autograd graph over 4096 rows
  traversed six times before one update (five `retain_graph=True` per-term
  diagnostic passes plus `total.backward()`). Measured throughput was 671 s for
  that single step, projecting the three-seed band to ~23 days at the observed
  operating point. Remedies A–E (recalibrate the guard / reduce the transient
  peak / change environment / accept the cost / build the missing resource
  preflight) each touch an owner-carved threshold, a declared telemetry
  contract, or the environment fingerprint. Row-count reduction is already
  foreclosed by the GAP-57-01 resolution note. The probe refuted the
  instrumentation hypothesis — removing five of six traversals recovered only
  8.6% and still tripped at 0.885 — while revealing a 4.4x throughput cost in
  the same traversals. Resolved under express owner delegation: memory-bounded
  microbatch execution is in-scope conformance (the ratified spec writes the
  constraint microbatching must satisfy, and the delivered index_add aggregation
  was built microbatch-safe for it), per-term telemetry becomes periodic with
  all ten field names retained, and the missing resource preflight is in scope.
  Environment change is preserved as the fallback. A blocking loss/gradient
  equivalence test makes the conformance claim falsifiable.
