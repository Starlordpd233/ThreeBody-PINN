## Fixed rung-4 parameters + edge R5 (planner build-engineering values, recorded with rationale)

- **PASS gate:** data-loss reduction ratio `L0 / Lf >= 1e3` (SPEC AC — the falsifiable operationalization of "near-zero"; the exact floor Lf is recorded evidence, not an invented ratified constant).
- **Model input `tau_ic13` — FIXED placeholder IC13 (finding claude-max HIGH #1, 3-reviewer cycle-3 consensus):** the overfit probe is the ONLY rung that calls `forward(tau_ic13, masses)`. It builds `tau_ic13(u_n) = [2*u_n - 1, IC13_placeholder]` for each fixture snapshot time `u_n = t_n / T` (T = `T_CHARACTERISTIC_TIME` from constants). The tau slot is derivable (tau = 2u - 1), but the IC13 slot is tanh-normalized with DATASET-WIDE statistics (`.claude/rules/pinn-reference.md:31`) — a Phase-39 artifact with NO Phase-38 source (the 38-03 `TrajectoryFixture` yields times/positions/velocities/masses only, not a normalized IC13). Pin `IC13_placeholder` = a FIXED all-zeros 13-vector (`torch.zeros(13)` on the resolved dtype/device), the same constant at every collocation time. Rationale: (1) a single-trajectory overfit conditions on a CONSTANT vector, so the net learns `tau -> r'` and the >=1e3x data-loss smoke is unaffected by the specific constant; (2) zeros is the neutral centroid of the tanh-normalized IC13 space (each normalized slot `tanh((z-mu)/(sigma+1e-8)) ~ 0` when z ~ mu), so it is the most defensible neutral placeholder AND unmistakable for real normalized data (feeding the RAW parsed IC values instead would put the conditioning vector wildly outside the model's expected [-1,1] tanh range — worse); (3) it invents NO metadata the spec defers — physically-normalized IC13 (tanh with Phase-39 dataset-wide statistics) is explicitly Phase-39 territory. This is a build-interface decision within CTX-15/16 planner discretion (parallel to the cycle-1 raw-`masses` pinning), NOT a spec-science adjudication, and the cycle-3 review consensus explicitly authorizes a fixed placeholder. The placeholder choice is recorded in raw.json provenance (labeled `ic13_placeholder: "zeros(13) — Phase-38 overfit smoke; physically-normalized IC13 deferred to Phase 39"`).
- **Bounded optimization + max-steps calibration (finding deepseek H2 / kimi H4 #5):** Adam on the DATA term only (overfit one trajectory), bounded by a documented `--max-steps` default of 3000 — an UNCALIBRATED build-engineering guess. Rationale: overfitting one trajectory's data term is a small, fast smoke of the model+COM wiring; a fixed cap makes non-convergence a bounded FAIL, never a hang. Calibration guidance: on a cap-reached FAIL the evidence's achieved ratio distinguishes a still-improving optimization (cap too low → re-run with a larger `--max-steps`) from a plateau (a genuine wiring problem). A one-shot calibration (run once with a generous cap, e.g. 10000, observe the convergence step, set the default to 2-3x that) is recommended and recorded in evidence; the default is NEVER a wiring verdict on its own.
- **Adam learning rate (finding cycle-2 #4 / deepseek M2 / claude-max LOW):** the Adam optimizer uses a documented default `--lr` of 1e-3 (the standard Adam default for this problem class), overridable via `--lr` and named as a build-engineering knob alongside `--max-steps`. Rationale: on a `first_omega_0=30` SIREN an ill-chosen learning rate can prevent the >=1e3x reduction within the step cap and produce a SPURIOUS bounded FAIL, so the LR is pinned (not left silent) and the actual LR is recorded in evidence. On a cap-reached FAIL with a still-improving ratio, the calibration guidance is to re-run with a larger `--max-steps` and/or a tuned `--lr`; the default LR is a build-engineering guess, never a wiring verdict on its own.

  - **pred_velocities** AD-derived from the model via the PHYS-02 `dr'/du` path (`pinn.physics_residual.componentwise_du`) — the model returns positions only, so velocities are never read from a nonexistent output head.
