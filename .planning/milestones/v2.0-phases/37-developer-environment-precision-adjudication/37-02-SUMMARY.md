**Reviewed committed environment pair + fail-closed normal setup + re-derivable M5 Pro provenance, all gated by an explicit (non-circular) first-lock seed**

## Performance

## Accomplishments

- **Non-circular first-lock (CTX-05):** `scripts/refresh-environment-lock.sh --seed` provisions a UNIQUE disposable task-owned prefix from `environment.yml` (never names `pinn-train`), validates it (torch 2.12 line, required imports, `pip check`), runs `pip freeze --all`, normalizes out conda-managed packages (`pip`/`packaging` report as `@ file:///` URLs and are reproduced by the conda section), rejects non-exact pins, re-derives a second freeze to confirm determinism, then atomically replaces the lock. Removes the disposable prefix on both success and failure.
- **Shared fail-closed bootstrap (CTX-01/02):** `scripts/lib/conda_bootstrap.sh` rejects non-Darwin/non-arm64 before download; discovers a compatible conda in priority order (`PINN_CONDA_EXE` → configured prefix → `~/miniforge3` → PATH, never Anaconda; each candidate must report `osx-arm64`); installs the pinned named release `Miniforge3-26.3.2-3-MacOSX-arm64.sh` (SHA-256 `59168f1e...98168`) into an empty prefix via batch `-b -p`. Never pipes a download to shell, overwrites an occupied prefix, calls `conda init`, or edits shell startup files.
- **One-command normal setup (CTX-03/04):** root `./setup.sh` requires BOTH committed inputs before any target mutation (fails with explicit remediation if either is absent, never dispatching the seed/refresh writer). First run: creates `pinn-train` from the YAML + replays the exact lock (`pip install --no-deps -r LOCK`) + `pip check`. Second run: validation-only ("pinn-train exists — validating only"). Prints exactly `source <base>/etc/profile.d/conda.sh && conda activate pinn-train` — does not spawn a subshell or mutate startup files.
- **Canonical provenance (CTX-06/07):** `scripts/verify_environment.py` builds the canonical fingerprint object (schema_version, timestamp, repository commit, structured platform/sw_vers, conda/python/packages/torch/MPS facts, exact lock path + SHA-256, structured verification checks) and renders both sorted-key JSON + Markdown from the one object. `--check-only` validates without writing. Exclusive UTC run dirs + atomic sibling-temp writes (non-overwriting). Secret-canary scan refuses to serialize any forbidden substring.
- **Retained M5 Pro evidence:** first-run fingerprint `20260712T141829Z` (env absent → created) + validation-only rerun `20260712T141846Z`. Both carry all 6 verification checks PASS, lock SHA `36e718cc...0293e3`, macOS 26.5.1 (25F80) arm64, torch 2.12.1 with MPS built+available+device_count=1. Markdown byte-identical to an independent re-derivation.

## Decisions Made

- **conda-managed package exclusion:** `pip freeze --all` reports `pip` and `packaging` as `@ file:///home/conda/feedstock_root/...` source URLs (they come from conda-forge, not PyPI). They are reproduced by `environment.yml`'s conda section, not the PyPI replay set, so `normalize_freeze` drops them. The lock contains only exact `name==version` PyPI pins.
- **sw_vers key mapping:** explicit map (`ProductName`→`product_name`, `ProductVersion`→`product_version`, `BuildVersion`→`build_version`). A generic `.replace(" ","_")` misses because sw_vers keys have no spaces.
- **write_fingerprint_pair dual call pattern:** `(obj, run_dir)` writes directly into the caller-owned dir; `(obj, root, run_id=X)` creates `root/X` exclusively. The verifier uses the 3-arg form for UTC run-id naming; setup.sh callers get deterministic exclusive paths.

## Deviations from Plan

### Auto-fixed Issues

**1. test_default_setup_has_no_dispatch_edge_to_seed was too broad**
- **Found during:** Task 37-02-02 (running Wave 0 contracts under pinn-train)
- **Issue:** the Wave 0 test did a naive substring check for `refresh-environment-lock.sh --seed` across the whole setup.sh source. The remediation text in `die` messages legitimately tells the owner to run the seed command manually — that is guidance, not a dispatch.
- **Fix:** the test now strips comments and string-literal contents, then checks that no dispatch token appears in executable code position.
- **Files modified:** tests/phase37/test_setup_contract.py
- **Verification:** 17 Wave 0 ENV-01/02 contract tests green under pinn-train.
- **Committed in:** this task's commit.

**2. sw_vers fields were empty in the first fingerprint generation**
- **Found during:** Task 37-02-02 (inspecting the first fingerprint JSON)
- **Issue:** `_sw_vers` lowercased keys but did not map `ProductName`→`product_name` (sw_vers keys have no spaces), so no field matched.
- **Fix:** explicit key map. Also hardened `render_fingerprint_markdown` to use `.get()` defensively.
- **Files modified:** scripts/verify_environment.py
- **Verification:** re-generated first + second fingerprints; sw_vers now reads `macOS 26.5.1 (25F80)`.
- **Committed in:** this task's commit.

**3. write_fingerprint_pair API ambiguity (collision test vs secret-canary test)**
- **Found during:** Task 37-02-02 (running Wave 0 contracts)
- **Issue:** the collision test called `(obj, run_dir)` expecting files directly in `run_dir`; the secret-canary test called `(obj, out_dir)` expecting the same; my original implementation always created a run_id subdir.
- **Fix:** dual call pattern — `(obj, run_dir)` writes directly; `(obj, root, run_id=X)` creates `root/X`. The verifier generates the UTC run_id and uses the 3-arg form.
- **Files modified:** scripts/verify_environment.py
- **Verification:** all 7 fingerprint contract tests green.
- **Committed in:** this task's commit.
