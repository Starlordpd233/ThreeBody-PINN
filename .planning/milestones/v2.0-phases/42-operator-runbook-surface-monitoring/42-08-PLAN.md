<objective>
Wire the composition root: install the signal handlers and lifecycle in
`pinn.train main()` so the sinks, heartbeat, and summary built in Waves 1-2 come
alive around the existing training loop, and so every exit path (normal, guard
HALT/exception, signal) leaves an honest, complete, handoff-able `runs/<name>/`.

Purpose: OPS-01/02 (the Launch/Resume surface + graceful signal semantics), OPS-05
(directory-contract completion + terminal summary), and Edges E2 (signal race +
atomic checkpoint) / E4 (partial-run honesty). Per Anti-Pattern #5, all
process-level side effects (signals, threads, handler attachment, SummaryWriter
construction) live ONLY here; the `pinn/training/` modules stay pure/importable.

Cross-AI review (cycle 1) corrected three structural gaps this plan now closes: a
REAL loop-interrupt seam (`RunController.should_stop`, checked at the Adam and
L-BFGS epoch boundaries) so a first SIGINT actually stops the `while True` curriculum
loop (finding #2); SYNCHRONOUS second-SIGINT escalation inside the handler so it fires
even when the main thread is stuck in a step, with a best-effort interrupted-summary
finalize (findings #3, #8); an EXPLICIT terminal-cause discriminator so `finished`
vs `failed` vs `interrupted` is derived from observable state, not the ambiguous
`HALT` return (finding #4); and `finally`-path handler removal/close so a repeated
in-process `main()` leaks no handlers (finding #5).

Output: `pinn/training/signals.py` (pure debounce helper + main-thread installer with a
synchronous escalation callback), a minimal additive `should_stop` seam in
`pinn/training/controllers.py`, and a wired `pinn/train.py main()`.
