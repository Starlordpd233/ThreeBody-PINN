THE D-08 BOUND IS DERIVED HERE — IMPLEMENT IT, DO NOT INVENT ONE. Cycle-3 review raised
this as the plan set's most fragile assertion (3-way consensus: codex MEDIUM, claude-max

below into its docstring verbatim in substance.

Step 1 — the exact frame identity. `preprocess_trajectory` (`preprocessing.py:196-205`)
applies an ORTHOGONAL rotation `R0` (so pairwise distances are preserved exactly), then
divides positions by `D` and velocities by `V = D/T`. `pinn/constants.py:24,31` locks
`D = cbrt(G*T**2)` with `G = 1`, `T = 10` — i.e. the PIPE-09 identity `D**3 == T**2`.
Therefore `T**2/D**2 == D**3/D**2 == D`, and per snapshot: the kinetic term satisfies
`K_new == D * K_old`, and the softened potential satisfies `V_new_at_eps ==
-sum_ij m_i*m_j / sqrt((s_ij/D)**2 + eps**2) == -D * sum_ij m_i*m_j /
sqrt(s_ij**2 + (D*eps)**2) == D * V_old_at_D_times_eps`. Hence
`H_new(t) == D * (K_old(t) + V_old_at_D_times_eps(t))` EXACTLY. The uniform factor `D`
cancels identically in the relative drift `eps_H = max_t |(H(t)-H(0))/H(0)|`, so the two
arms can differ ONLY because the same numeric `eps` behaves as an effective `D*eps` in
old-frame units. That is exactly the softening-floor asymmetry D-08 names — now
quantified rather than asserted. The identity also holds for the validation-side reading,
whose velocity is a divided difference of positions with respect to the supplied times
(`gate_metrics.py:84-123`): that operator is linear in positions with coefficients
`1/(t[k+1]-t[k-1])`, so scaling positions by `1/D` and times by `1/T` scales its output
by `T/D == 1/V`, exactly as the stored velocities scale.

Step 2 — the softening residual (exact inequality). Let `delta(t) =
V_old_at_D_times_eps(t) - V_old_at_eps(t) >= 0`, so `H_new(t)/D == H_old(t) + delta(t)`.
With `f(a) = (s**2 + a**2) ** -0.5`, the difference of two square roots gives
`f(eps) - f(D*eps) == (D**2 - 1) * eps**2 / ( (sqrt(s**2 + D**2*eps**2) +
sqrt(s**2 + eps**2)) * sqrt(s**2 + eps**2) * sqrt(s**2 + D**2*eps**2) )`, which is
bounded above by `(D**2 - 1) * eps**2 / (2 * s**3)`. Summing the three pairs and
maximizing over the snapshots compared, `delta_max = 0.5 * (D**2 - 1) * eps**2 *
sum_over_pairs( m_i * m_j / s_ij_min**3 )`, where `s_ij_min = min_t norm(r_old_i(t) -
r_old_j(t))` is that PAIR's closest approach in OLD-frame (raw, COM-gauged, unscaled)
units — read from the trajectory's own geometry, an input, never a metric output.

Step 3 — propagation into the ratio (exact inequality). Write `a = H_old(0)`,
`e = delta(0)`, `Delta(t) = H_old(t) - H_old(0)`, `d(t) = delta(t) - delta(0)`. Then
`g_new(t) - g_old(t) == (a*d(t) - Delta(t)*e) / (a * (a + e))`, and since `|d| <=
delta_total`, `|e| <= delta_total`, and `max_t |Delta|/|a| == eps_h_old`, we get
`abs(eps_h_new - eps_h_old) <= delta_total * (1 + eps_h_old) / (abs(a) - delta_total)`.
Note `eps_h_old` enters as the propagation amplification factor produced by this algebra
— it is the measured baseline whose error bar is being computed, exactly as a measurement
uncertainty depends on the measurement. It is NOT a fitted quantity and does not make the
bound output-tuned. The bound is valid only while `delta_total < abs(a)`; if that fails,
raise/fail rather than widen (see the behavior block).

Step 4 — the float64 allowance, folded into `delta_total`. Two cancellations that are
exact in real arithmetic are only near-exact in float64: (1) `T**2/D**2 == D` holds to a
few ULP because `D` is formed by `100.0 ** (1.0/3.0)`; (2) each `H` evaluation
accumulates a handful of float64 terms. Both act as an extra ABSOLUTE perturbation of
`H_old`, so set `delta_round = 4*u*K_max + 8*u*(K_max + absV_max)` with
`u = numpy.finfo(numpy.float64).eps / 2`, `K_max = max_t K_old(t)`,
`absV_max = max_t abs(V_old_at_eps(t))`, and use `delta_total = delta_max + delta_round`
throughout Step 3. The literals `4` and `8` are operation counts (one pow, one square,
one divide for the `D` identity; three pairwise potential terms, three kinetic terms, one
sum and one ratio for the assembly) — not fudge factors, and not to be raised.

Each reading supplies its own `eps` from its own module default (validation-side
`EPS_INV`, loss-side `EPS_SOFT`); the helper is called once per reading with that value,
so the bound automatically tightens for the validation arm and loosens for the loss arm
without any per-arm constant being chosen.
