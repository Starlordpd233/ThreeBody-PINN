## 1. Final Issue 03 Resolution

### 1.1 Posture and the locked baseline

The framework specifications `ctl_instruction.md` and `pinn_architecture.md` are the source of truth. The issue document `03-curriculum-and-training-loop.md` is non-authoritative auditing material, and live-code citations inside it are overridden. The single most consequential structural fact of this issue is that **the issue document was largely written against an earlier spec revision**, so a substantial fraction of the "open questions" it poses are not open at all — they were settled by the current PHYS-05 / Phase-17–19 spec state, and the issue doc's framing of them is simply stale. Separating genuine open work from stale framing is the core of the adjudication, and it is the place where the reports diverge most sharply in quality.

The following are **locked SCOPE-12 hard constraints** (`scope-12-hard-constraints.md`, items 1–7), corroborated by `claims-register.md` and `verified-facts-reference.md`. They are not adjudicable and no proposal that contradicts them is selectable:

The network input is the 14-dimensional vector `[τ, IC₁₃]` with a fixed-gauge Jacobi-state encoding; invariant-heavy descriptors (`L_norm`, `τ_L`, `Q`, `s_min`) are metadata, never network inputs. The output carries a hard mass-weighted center-of-mass projection head applied before any loss or gradient, so linear-momentum conservation is structural and there is no separate momentum-penalty loss. Loss-side softening is the matched-Plummer form `r_safe = √(‖Δr′‖² + ε²)` with `ε_train = 1e-5` (PHYS-03); the additive `(‖r‖ + ε)` form is prohibited. The characteristic length is the raw-mass `D = (G·T²)^(1/3) ≈ 4.6416` (PHYS-01, CLM-19, `verified`); the total-mass `D = 6.694` (CLM-01) was examined and rejected by v1.5 Phase 25 (EVID-10), and "no configuration parameter may select the mass-fraction form." The data-side PIPE-01..10 / VAL-01..04 contracts and the stage-query contracts (`sample_replay`, `sample_lookahead`, `has_stage`) are locked. A small set of spec *contracts* carry **no CLM row** and are not empirical claims: `ε_plateau = 1e-5`, `ε_phys = 1e-4`, `ε_energy = 1e-4`, the `ε_H = 1e-4·S_H` floor, the `τ_L` split softening `ε_pert = 1e-8` / `ε_soft = 1e-10`, the ALM `μ_p` clamp `[1e-4, 100]`, the gradient-clip `5.0 × median` factor and `C` schedule `7–10 / 5 / 3`, and the PHYS-05 warmup schedule. Finally, per the D-17 verification boundary, **v1.6 has no in-milestone empirical-verification phase**, so every figure not in `verified-facts-reference.md` (the issue-03 stage counts, the design-constant tables, the `D = 6.694` derivation) is `claimed-unverified` and must not be relied on as fact.

### 1.2 The three decisions reserved for the framework owner

These are posed unsettled in `framed-research-questions.md` Section 2 and are surfaced — not decided — here. In each case the spec already establishes a baseline, and the issue doc's framing of the choice is partly incorrect.

**The causal-training-mode decision.** The issue doc frames a choice between Option A (causal weighting), Option B (global sampling + dense ALM), and Option C (time-windowed causal-ALM hybrid), and asserts Option B is the "current SOT." This assertion is factually wrong against the current spec. `ctl_instruction.md` ("Loss Function Formulation" / "Phase 2: Total Training Loss") and `pinn_architecture.md` §3.2 / §4.1 (PHYS-05) **already adopt causal weighting** `w_n = exp(−η_c · Σ_{m<n} stopgrad(R̄_m))` with `w_1 = 1`, `η_c = 1` as the default, and **explicitly reject** the dense-residual pseudo-ALM; ALM survives only as a P2 ablation on scalar conservation constraints. So Option A is the current baseline, Option B is the explicitly rejected formulation, and Option C is a large un-specced rewrite of the Adam phase. The `stopgrad` in the causal weight is itself the mechanism that blunts the "causal-firewall" risk attributed to Option A: gradients do not flow through the exponential weights, so an early stiffness spike depresses later weights without making the weight term adversarial. The owner's real decision is therefore narrow — confirm the causal-weighting baseline as written, optionally consider a stage-dependent `η_c`, and optionally scope Option C as future work — and the issue doc's Section-2 causal framing should be annotated *obsolete, superseded by PHYS-05*. No A/B/C selection is made here. There is no empirical comparison of A/B/C in the attached materials.

**The s_min-frame decision.** The spec is already dual-context and internally consistent: `ctl_instruction.md` Step 3 item 1 defines `s_min` from "true pairwise separations (no softening)" as a geometric close-encounter detector for the curriculum gate, while static invariants use `ε_inv = 1e-10` (in `V` only) and training losses use the locked `ε_train = 1e-5`. The issue doc's Option A matches this baseline and Option B (softened everywhere) contradicts it, so on its face the decision is "confirm status quo." The subtlety that must be surfaced: the issue doc's Option A also references a training-loss collision criterion `max(s_min, ε_soft)` that **does not exist in the current spec**. Stage 6 (`s_min < 0.5 OR |E| < 0.01`) is a curriculum gate, not a loss term, and an additive `max(s_min, ε)` would itself be the prohibited PHYS-03 anti-pattern. So the issue doc is not tidying an existing criterion; it is implicitly proposing a *new* close-encounter loss term. The owner's decision is therefore between (a) confirming the status quo — unsoftened `s_min` for the gate, no training-loss collision term, always logging the unsoftened value — and (b) commissioning a genuinely new close-encounter loss term, which would have to be designed from scratch under PHYS-03 with its own weight schedule and an explicit interaction analysis against the causal weighting.

**The epsilon-strategy decision.** The loss-side `ε_train = 1e-5` is locked and is explicitly *not* part of this decision. The genuinely open question is only whether a distinct static/invariant softening legitimately coexists with it. The spec already answers this as Option B (dual-context): `ctl_instruction.md` Step 3 item 1 states `ε_inv = 1e-10` is "context-specific for offline invariant computation and is distinct from the training-time softening `ε_train = 1e-5`," and `pinn_architecture.md` §3.4 carries the dual-epsilon visibility note. Option A (collapse offline to `1e-5`) would coarsen the offline invariants and the stage assignment that depends on them; Option C (unify at `1e-10`) is incompatible with the locked loss side and is argued against on double-precision grounds. The owner's decision reduces to ratifying the existing dual-context arrangement, and the issue doc's "five-order-of-magnitude contradiction / truncated justification" framing should be annotated as resolved by the current spec text. Whether `ε_inv = 1e-10` materially changes stage assignments versus `1e-5` is unverified in the attached materials and is logged as a FUT empirical check.

### 1.3 Findings confirmed by the spec (issue-doc framing stale or already implemented)

**M7 — `τ_L` excluded from the IC vector: accepted.** `ctl_instruction.md` Step 4 already excludes `τ_L` (a derived dynamical property, not an initial invariant) from `IC₁₃` and retains it for stage gating only, exactly as the issue doc recommends. No change beyond removing any lingering text implying `τ_L` is an input.

**NS-12 — componentwise automatic differentiation: accepted.** `pinn_architecture.md` §5.3.1 (PHYS-02) is the canonical componentwise normalized-time AD contract: it requires all nine `dr′_{i,α}/du`, forbids the `torch.autograd.grad(r.sum(), u, …)` summed-output anti-pattern that NS-12 warns against, lists three acceptable patterns (`jacrev`+`vmap`, per-component loop, full-Jacobian), and includes a worked synthetic-trajectory derivative test. Fully satisfied; no change.

**B-07 — replay/lookahead batch construction: accepted, with one pseudocode fix.** `ctl_instruction.md` ("Mini-Batch Construction with Lookahead Sampling") already specifies 240 replay trajectories from stages ≤ k, 16 lookahead from stage k+1 (batch 256), `n_pts(traj) = min(32, n_snapshots)`, and the 50/50 acceleration-weighted-plus-uniform split (seeded, without replacement). The issue doc's "not implemented" is a description of legacy code, which is overridden. The one reconciliation item is a bug in the audit's §6 pseudocode, which draws a fixed 32 via `np.random.choice(..., replace=False)`; this must be corrected to `min(32, n_snapshots)`, since per-trajectory snapshot counts can fall below 32 even though the verified *medians* are 61 / 127 / 1003 (CLM-16). The counts 240 / 16 / 8192 / 4096 are `claimed-unverified` design constants (CLM-12).

**B-08 — data-fidelity vs collocation separation: modified (reconcile, then make explicit).** `pinn_architecture.md` §3.1 (data term, `N_data = 256 × 32 = 8192`) and §3.2 (collocation residual, `n_col = 4096`) already define two independent point sets with distinct sampling and loss roles, so the issue doc's "conflation" claim is stale. Two reconciliations are required. First, the discipline is *implicit* in the spec but not encoded in the batch constructor, and should be made explicit there. Second — and this is the substantive correction — the data term is **Huber**, not the L1/MAE the issue doc assumes; this is resolved jointly with NS-18 below.

**NS-18 — loss-component scaling contract: modified (L1 → Huber).** The spec's units contract is already coherent: `pinn_architecture.md` §3.1 uses a **Huber** data term (`δ_r = 1`) on scaled positions `r′ = r/D` with the locked `D ≈ 4.6416`, §3.2 the physics residual with `ε_train = 1e-5` and causal weighting, §3.4 the energy regularizer with the same `ε_train`, and §4.1 composes them. The issue doc's "`L_data` uses L1/MAE" is obsolete pre-Huber prose and the spec explicitly states the Huber term replaces it. Adopt the spec's Huber data contract and confirm all terms operate in dimensionless `G = 1` units under the locked `D` and `ε_train`. A secondary diagnostic, raised by one report and worth carrying: the same `δ = 1.0` default appears on both the *data* Huber (NS-18) and the *energy* Huber (NS-13), but the two live on different residual scales — data residuals are O(0.1–1) in scaled-position units, where `δ_r = 1` is plausibly appropriate, whereas the normalized energy residual is much smaller — so the two `δ` defaults should be audited together rather than treated as one knob.

**M14 — gradient-clipping merge: accepted, owner picks the stages-0–1 value.** `pinn_architecture.md` §4.4 gives `clip = 5.0 × median` of the last 100 gradient norms; `ctl_instruction.md` ("Adaptive Median-Based Gradient Clipping") gives the curriculum-aware `C` schedule (stages 0–1: 7–10; 2–3: 5; 4–6: 3). These are not truly in conflict — the §4.4 factor of 5.0 *is* the stages-2–3 value of the same schedule, presented standalone. Adopt the merge `clip = C_stage · median(grad_norm_history[-100:])`, exactly as the issue doc proposes, and update §4.4 to reference the per-stage schedule. The one open point: the issue doc's `C_table` (CLM-10, `claimed-unverified`) sets stages 0–1 to **8.5**, an arbitrary midpoint of the spec's `[7, 10]` range that is not spec-endorsed. The owner should choose a concrete value (or anneal rule) within `[7, 10]`; 8.5, 7, and 10 are equally defensible, so 8.5 is recorded as one option, not as a decision.

**`D = 6.694` vs `D ≈ 4.6416`: rejected / locked.** `D ≈ 4.6416` is the locked raw-mass value (CLM-19), and `4.6416³ ≈ 100 = T²` is internally consistent with `T = 10`. The issue doc's `D = 6.694` (CLM-01, total-mass) is rejected. Beyond the settled value, there is a useful code-hygiene finding: in the issue doc's `compute_tau_L`, the `D = cbrt(G·M_tot_ref·T_scale²) = 6.694` and `V = D/T_scale` lines appear to be computed but unused — the acceleration uses raw masses with no `D`/`V` dependence, and integration runs on a state assembled directly from `r′`/`v′`. If that reading holds (it requires code inspection, which is outside the attached materials and is logged as a gap), the `6.694` error is dead code with no numerical effect on `τ_L`, a hygiene defect rather than a results defect. Regardless, the `6.694` reference should be purged (or set to the locked value) to prevent contamination if the variable is ever activated, with a regression test confirming `τ_L` is unchanged.

**ALM `μ_p` clamp: modified (misattributed; conditional/FUT).** The issue doc's `μ_p = clip(μ_p, 1e-4, 100.0)` and the surrounding RMSprop-style machinery belong to the dense-residual pseudo-ALM that the spec explicitly rejects. The only surviving ALM is the P2 ablation on scalar conservation constraints (`pinn_architecture.md` §4.2), whose multipliers are per-constraint (energy drift `c_E`, angular-momentum drift `c_{L,α}`), updated only between Adam epochs and never inside L-BFGS. In the baseline loss the clamp has nothing to attach to. Annotate the finding as misattributed; if and when the P2 ablation is activated, a clamp on its scalar-constraint multipliers is a reasonable safety addition then. Consistent with this, the claims register lists the `μ_p` clamp `[1e-4, 100]` among the non-dataset spec-parameter exclusions (no CLM row).

### 1.4 Findings that are contested or source-silent (surfaced or deferred, with dissents preserved)

**M15 — energy-loss weight: the issue-doc proposal is rejected; PHYS-05 stands; a narrow sufficiency question is deferred.** This is the clearest case of stale framing. The spec PHYS-05 schedule (`pinn_architecture.md` §4.1) is `λ_E^max(k) = λ_L^max(k) = {0 for k ∈ {0,1}; 10^{k−4} for k ∈ {2,3,4}; 1 for k ∈ {5,6}}` with linear warmup `I_warm = min(2000, 0.1·N_Adam)` — i.e. the energy term is **off** at stages 0–1 and **capped at 1.0**. The issue doc's premise that `λ_E` rises toward 1000 and overwhelms physics/data comes from an even older schedule (the `review_of_framework.md` `λ_E → 1e3` regime), and its capped-hybrid `cap_table = {0:1, 1:5, 2:20, 3:50, 4:100, 5:200, 6:500}` (CLM-11) is 10×–500× *larger* than the locked spec at every stage — so adopting it would make the cap *less* conservative than the spec it claims to fix. The issue doc's CLM-11 cap_table is rejected as obsolete; the spec schedule governs. The only residual is a genuinely open, unverified question — whether the `1.0` cap at stages 5–6 is itself sufficient — which is deferred as a FUT empirical check, to be settled by an ablation rather than by the `500` figure. (The dominance safeguard the issue doc bundles in is a separate, evidence-gated proposal; one report flagged that the safeguard as written is internally inconsistent — one rule compares `λ_E·L_E` against `10·L_data`, another halves `λ_E` when `L_E < 0.01`, and neither accounts for the physics or IC terms — so it should not be adopted as-is.)

**M16 — `dt_out`-aware collocation scaling: deferred (genuine source conflict; do not adopt either direction).** `ctl_instruction.md` exposes `n_snapshots` / `dt_out` as loader metadata but explicitly labels the M16 scaling rule a deferred forward-interface item ("not used here"); `pinn_architecture.md` §3.2 uses a fixed `n_col = 4096`. The per-variant `dt_out` is verified (CLM-17: std 0.17 / hier-base 0.08 / gold 0.01), but the scaling *rule* is `claimed-unverified` (CLM-20). The sources genuinely conflict on the rule: the issue doc proposes `n_col ∝ dt_base / dt_out` (gold 1×, hier ≈0.125×, std ≈0.059×), while `review_of_framework.md` §5.3 treats collocation density as resolution-*independent* and applies no special handling. The direction is also physically debatable: `dt_base/dt_out` gives the sparsest (lowest-resolution) trajectories the *fewest* collocation points, which is arguably backwards, since those are the trajectories that most need physics-informed interpolation between snapshots — and because collocation residuals are sampled from the continuous `[0, T]` domain rather than at snapshot times, coupling `n_col` to `dt_out` at all is weakly motivated; trajectory difficulty (close encounters) is the better driver. The honest finding is "insufficient evidence": keep the deferral (fixed `n_col`) until an ablation studies collocation-density × resolution, and do not adopt either direction provisionally. This disposition tracks the reports that surfaced the §5.3 conflict and resisted the audit-verbatim direction (R1, R3, R7) over those that confirmed `dt_base/dt_out` while omitting §5.3 (R2, R4, R6); the canonical sources support the former because §5.3 genuinely opposes the rule.

**D5 — stage-transition criteria / dual-path fallback: surfaced (direction sound; structure and the load-bearing relaxation are owner-and-empirical, with a dissent on the fallback's semantics).** `ctl_instruction.md` ("Stage Transition Criteria") encodes four strict criteria — training plateau (`ε_plateau = 1e-5`, patience 200, `β = 0.98`), validation stability in a monotonic / `≤ min` form, physics residual `ε_phys = 1e-4`, and energy drift `ε_energy = 1e-4` with the locked `ε_H` floor — and carries the spec author's own note questioning their attainability with limited data. It encodes **no** fallback path, so the issue doc's observation that strict-only criteria can stall is a real gap and the dual-path direction is sound. The numbers, however, are all `claimed-unverified`: the fallback max-epochs `{0:500 … 6:1200}` (CLM-09), the per-stage `ε_phys`/`ε_energy` relaxation `5e-3 … 1e-4` (CLM-08, "not fixed"), and the Stage-0 pilot are design hypotheses to calibrate, not constants to lock. The single load-bearing decision is relaxing criterion 2 from `≤ min` to `percentile_10` — that shifts the gate from "never regress" to "mostly don't regress," which for chaotic systems with inherently non-monotonic long-horizon validation loss is defensible but is the owner's call. The materials contain no attainability data, so this is surfaced with graduated options (keep strict-only plus a max-epochs cap and NaN rollback; full dual-path with `percentile_10` and per-stage tables; or an intermediate), and no option is selected.

> **Dissent preserved (R3) — the fallback must not be modeled as auto-advance.** One report argues, correctly, that the issue doc's "Path B" conflates three semantically different events under a single "advance" trigger, and that they must be separated: **ADVANCE** (quality-gated promotion), **RECOVER** (NaN rollback to a checkpoint — a recovery, not a promotion), and **HALT for owner review** (max-epochs or stagnation reached — an escalation, not a silent promotion). Treating a NaN-rollback or a max-epochs timeout as a reason to move to the next stage risks promoting an unconverged model. This dissent is well-founded against the issue-doc text and is recorded as a design constraint on any dual-path implementation: a fallback that fires on stagnation or NaN should *stop* and surface, not *advance*.

**M6 — `L_norm` clamping: modified (the IC-mapping rationale is obsolete; clamp, if used, is metadata-only).** Under the locked 14D `[τ, IC₁₃]` contract, `L_norm` is metadata (staging, diagnostics, loss-scaling), not an IC slot; `compute_L_norm` returns `L/(L_max + eps)` and can legitimately exceed 1. The issue doc's rationale — "clip before the `2x−1` IC mapping or the IC component exceeds 1" — therefore no longer applies, because `L_norm` is never mapped into the network input. The residual valid concern is narrow: stage-gating logic should not assume `L_norm ∈ [0, 1]`. The disposition is that no source clamp is needed for the network; any staging consumer that needs a bound applies `clip` at the point of use, and (per R3) the raw value should be persisted with a validity flag rather than overwritten, so a `L_norm > 1` is not silently hidden — it may indicate a super-circular configuration *or* a degenerate denominator, and the two should remain distinguishable.

> **Divergence preserved (R6 vs the rest).** One report (R6) endorses the issue doc's fix as written — inserting a hard `np.clip(L_norm, 0, 1)` into the processing chain on the premise that `L_norm` still feeds the IC vector through the `2x−1` mapping. That premise is obsolete under the locked 14D contract (and R6 internally contradicts its own earlier statement of that lock). Every other report (R1, R2, R3, R4, R5, R7) treats the IC-mapping framing as dead and the clamp as metadata-only at most. The locked contract decides this against R6's framing. Within the majority there is a finer spread on the metadata clamp itself: persist-raw-plus-flag-plus-separate-clipped-feature (R3), clip at the point of use (R2, R4, R7), or a harmless `[0,1]` metadata clamp (R1).

**NS-13 — Huber energy `δ`: deferred (empirical/FUT; do not change speculatively).** `pinn_architecture.md` §3.4 (PHYS-04) fixes the energy-Huber transition at `δ = 1.0`, applied to the relative drift `ΔH_n = (H_ε − H_ε(r_0)) / (|H_ε(r_0)| + ε_H)`. The concern is valid in principle: because the residual is normalized and `|H_ε(r_0)|` is O(1) for bound systems, `|ΔH|` is plausibly O(1e-4 … 1e-2), so `δ = 1.0` places essentially all samples in the quadratic branch and the Huber loss degenerates to L2, losing its outlier robustness. But the actual `|ΔH|` distribution is not in the attached materials, so the correct `δ` cannot be derived. The disposition is to defer: measure normalized `|ΔH|` per stage in the Stage-0 pilot, then set `δ` near a high quantile (the issue doc's 0.01–0.1 is a reasonable starting hypothesis, possibly stage-dependent), and do not change `δ` speculatively in the meantime. This is also where the reports disagree on a value, and the disagreement is preserved rather than averaged (see the register).

**Data-driven adaptive stage assignment: surfaced (well-motivated in principle; boundaries, cluster count, and population threshold are owner decisions; locked PIPE contracts constrain the mechanism).** The spec baseline (`ctl_instruction.md` Step 5 + "Multi-Stage Data Stratification") is threshold-based, keyed by `record_key`, with hierarchical data in stages **0–2** and quasi-random in **3–6**, and the spec author's own note invites a data-driven scan because the virial ratio is not preserved under quasi-random Sobol sampling (the `Q ∝ s³` distortion, corroborated in `sampling_method.md`, which documents `scale_range = [0.8, 1.2]` enabled at coordinate `u₄`). So the motivation is grounded. The methodology must, however, respect three hard boundaries and resolve three conflicts. The hard boundaries: it must not violate the locked PIPE-01..10 stage-query contracts, which require stable materialized integer stage labels per `record_key` (so clustering must run *offline for boundary discovery* and then be *frozen into fixed thresholds* — K-means must not run at training time); it must preserve the 184 standard-IDs-without-gold hole (CLM-14) and the Stage-5 gold obligation; and CLM-02..07 stage counts are `claimed-unverified` and are invalidated until the EDA actually executes (the `~2,565` figure that appears alongside them is the verified gold count CLM-15, not a stage count). The conflicts to put to the owner: the **stage-mapping conflict** — the spec places hierarchical in stages 0–2 while `stage_strat_revision.md` places it in 0–1 (quasi-random 2–6); the **cluster-count conflict and cardinality problem** — `stage_strat_revision.md` uses `k = 5` and the issue doc `k = 6–7`, and a `k = 6` clustering cannot directly populate the seven-stage (0–6) label space without splitting a cluster or defining an extra stage; and the **population-safeguard conflict** — `> 5%` per stage (`stage_strat_revision.md`) versus `> 10%` (issue doc). The recommended *shape* (not a decision) is hybrid: discover boundaries offline with a fixed seed and versioned feature normalization plus a population safeguard, encode the discovered boundaries as fixed thresholds producing a stable seven-stage labeling, and retain the existing thresholds as a fallback if clustering fails. The 0–2-vs-0–1 boundary and the cluster-count→stage mapping should be decided from the Stage-0/pilot EDA, not pre-committed. (`stage_strat_revision.md` also carries an internal `I3` DataFrame-schema inconsistency, flagged in its own source-issues block as SI-SSR-001, which lowers confidence in its schema.)

**`τ_L` / `L_max` formulas: split — `L_max` accepted, `τ_L` estimator surfaced/deferred, with interpretation and unit dissents.** `L_max = M_total · r_char · v_char` with `v_char = √(2|E|/M_total)` is confirmed by consensus of `ctl_instruction.md` Step 3 item 2, the issue doc, and `review_of_framework.md` §1.1, and is accepted. The `τ_L` *estimator*, by contrast, is specified three different ways across the sources and is surfaced for owner clarification: the spec (`ctl_instruction.md` Step 3 item 5) designates a **Rosenstein-style** estimator on the Brutus time series (delay embedding, nearest neighbors with a Theiler window, divergence-curve slope) and recommends a fast batch approximation for ~15K trajectories; the issue doc inlines a **shadow-trajectory** routine (perturb by `ε_pert = 1e-8`, re-integrate nominal and perturbed, track divergence, with potential softening `ε_soft = 1e-10`) while *also* mentioning "PCA+Rosenstein"; and `review_of_framework.md` §1.1 uses a **Benettin** integration. These are different families (Rosenstein works from existing trajectory data and is cheap and robust for batch use; shadow-trajectory and Benettin require re-integration), and which one is actually implemented cannot be determined from the materials. The recommended posture is to clarify the implemented method and align to the spec's Rosenstein designation for batch cost/robustness, retaining shadow-trajectory only as a calibration diagnostic — but this is the owner's call. The split softening `ε_soft = 1e-10` is numerically equal to `ε_inv` but is an independent offline parameter and must not be collapsed into the locked loss-side `1e-5`.

> **Dissents and ambiguities preserved.** (i) *L_max interpretation (R3):* the spec's own wording describes `L_max` as a characteristic circular-orbit scale, not a proven physical maximum, so a `L_norm > 1` is expected rather than an error, and a rename to `L_scale` would reduce the implication of a hard bound; the issue doc and `review_of_framework.md` overstate it as a maximum. ## 6. Non-Independent-Input Note

The reports were treated as seven accounts of the same evidence, not as seven votes. Concretely: the disposition for every claim was fixed against the canonical sources *before* tallying which reports agreed, so heavy convergence (e.g. on the locked `D`, the causal-mode mischaracterization, the obsolete M15 premise, the `review_of_framework.md` §2.2/§4.3 anti-patterns, the `L_max` formula, the NS-12/M7 confirmations) added no evidential weight — each convergent claim was independently re-verified against `ctl_instruction.md`, `pinn_architecture.md`, the claims register, and the SCOPE-12 constraints, and all held on their own merits. Where a claim rested only on report agreement and could not be traced to a canonical source, it was surfaced or deferred, not accepted.

Overlap was handled by attribution to the underlying source rather than to the reports. When several reports made the same point, the claim matrix records all of them in `supporting_R#`, but the `canonical_source_basis` column — not the count — carries the disposition. This is visible in the matrix: claims with six or seven supporting reports (M7, NS-12, the D-conflict) and claims with two or three (M15-kept-PHYS-05, M16-defer, NS-13-defer) are dispositioned by the same standard, because the number of restatements is not part of the standard.

Apparent synthesis was neither rewarded nor penalized. Some reports clearly subsume others' content — R7 and R1 in particular read as comprehensive syntheses that restate most of the panel — but no report was up-weighted for breadth of restatement. What earned a report influence on a *specific* claim was a verifiable tie to a canonical section that the disposition already rested on. This is why R3, which restates less, is nonetheless the decisive source on several minority findings (the D5 advance/recover/halt separation, the `L_max` interpretation, the non-Plummer `τ_L` softening, the M15 safeguard inconsistency): those points trace to spec wording and to the issue-doc's own text, independent of how many other reports mentioned them. Minority and dissenting positions were preserved in §3 even when a majority disagreed, precisely because majority size is not evidence.

Differential reliability was assessed on grounds that do not require knowing model identity — internal consistency, sourcing, and correctness against the attached bundle. Two findings followed from this. First, **R6 cites only the non-authoritative issue document** (`03-curriculum-and-training-loop.md`) as its sole reference and reproduces several of that document's superseded fixes (the M6 hard-clip on the obsolete IC-feeding premise, the M15 cap_table as mandatory, `δ → 0.01`, the L1 data term); because its agreements with the spec-grounded reports are unsupported by its own sourcing and several of its independent positions are wrong against the locked constraints, it was given no weight for restating consensus and its divergences were resolved against it by canonical basis. Second, **R5 and R6 each declared attached files unavailable** (R5: `stage_strat_revision.md`; R6: `pinn_architecture.md`, `sampling_method.md`, `stage_strat_revision.md`, and a claimed truncation of `framed-research-questions.md`), and returned weakened adjudications or "Insufficient Evidence" as a result. The package rule that "material a report cites but that is not attached is unavailable" was applied in its mirror form: material a report claims is unavailable but that *is* attached remains available to the adjudicator. All five files were verified present and complete (by section sha256 and direct inspection — including `pinn_architecture.md`, whose correct hash `318f297a…` R6 itself quotes while calling the file absent), so the affected findings were adjudicated on the real sources and the reports' spurious gaps were excluded from §4. None of these reliability judgments assumes anything about which model produced which report; they rest entirely on what each report cites and whether it matches the attached bundle.
